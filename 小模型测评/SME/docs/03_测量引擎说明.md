# 03 测量引擎说明

> 原则：Demo 不调用引擎；实测优先导入，缺指标才调用引擎；引擎缺依赖/资产时明确失败，不伪造数值。
> 所有结果都带 `provenance`：`measured_model`（真实模型推理）、`measured_rule`（可解释规则）、`proxy`（代理指标）、`imported`（客户导入）。

## 0. 协议审计与离线实验

- 每个引擎返回的 `EngineResult` 现在统一落成任务结果的 `result.engine` 块：
  `{"provenance": {...}, "meta": {...}, "missing": [...], "notes": [...]}`。
  `/api/v1/eval/tasks/{id}`、单任务 JSON/Markdown 报告和算子 `result.json` 都保留该块；只写最终分数、丢掉训练配置/种子/语料的做法不再允许。
- `meta.engineVersion` 是复现实验的最小版本锚点：
  `text-mlm-char-v1`、`text-bert-mlm-v2`、`image-proxy-v1`、`audio-asr-v2`、
  `video-vqa-v2`、`benchmark-import-v2`。
  `meta` 同时保留 seed、样本数、模型/训练配置、训练语料、ASR 后端或标签配置等实际字段；没有的字段不补造。
- 视频离线 VQA/MOS 入口：
  `python tools\run_video_vqa.py --videos <目录> --out <目录> [--labels mos.csv]`；
  没有真实逐视频 MOS 时只输出 `labels_missing`，不产生 SRCC/PLCC。
- 离线单次实验：
  `python tools\run_protocol_experiment.py --type image --samples <清单> --out <目录> --seed 42`
  输出 `protocol.json`、`measurements.jsonl`、`summary.json`，与 API 共用 `app/experiments/runner.py` 和 `rules.evaluate`。
- 图像训练式对照的**线性探针**入口：
  `python tools\run_image_classification.py --ours <D_ours> --ref <D_ref> --eval <固定E> --output <json>`；
  需要 `pip install -r requirements-image.txt`。它冻结同一个 ImageNet backbone，只训练同架构线性头，且强制 D_ours/D_ref 训练条数、每类条数、类别顺序、seed 和 E 对齐。它**不是** ResNet 全量微调，也不改变在线图像引擎的 proxy 口径。

## 1. 文本（`app/engines/text.py`）

- 在线引擎版本：无本地 BERT 时 `text-mlm-char-v1`；配置本地 BERT 时
  `text-bert-mlm-v2`。
- 字符级兜底：embedding 128、2 层 TransformerEncoder、4 heads、max_len 128；
  仅用于回归测试/快速联调，不冒充 BERT 下游结论。
- BERT 路径：`SME_TEXT_MODEL_PATH` 指向 `weight/bert-base-chinese` 时加载本地
  `AutoModelForMaskedLM` 和 tokenizer；MLM 掩码 15%，替换遵循 80% `[MASK]`、
  10% 随机 token、10% 保留原 token，默认学习率 **2e-5**（`SME_TEXT_MLM_LR`
  可覆盖），默认 1 epoch（`SME_TEXT_BERT_EPOCHS` 可覆盖），不再使用旧的 5e-5。
- 候选模型：在待评估样本的 `input` 上训练（90/10 划分，固定 seed）。
- 基线模型：在外部数据根目录的 `reference/text_reference.jsonl` 上训练；同架构、
  同超参、同字符量，体现“同模型同数据量”。该文件自 2026-11-04 起使用 CLUENER
  train 派生的 1,000 条中文句段，不是 CLUE 测试集；旧 22 条语料保留为
  `reference/text_reference_legacy.jsonl` 仅作回归对照。
- 逐样本：固定 mask 15% token，两个模型分别预测被 mask 位置：
  - `accuracy` = 正确数 / mask 数 ×100；
  - `f1` = 对被 mask token 的 macro-F1 ×100（单类别时用 accuracy 兜底）；
  - `lossCv` = token loss 标准差 / 均值（均值≈0 时为 0），截断到 0–1。
- 上限：最多 5000 条；训练集截断到 2000 条/40000 字符/6000 chunks；默认超时
  240s；CPU 可跑。
- 复现：`seed` 固定；同一数据/配置/环境结果一致（浮点误差除外）。
- 失败：torch 不可用/训练失败 → `ENGINE_UNAVAILABLE` / `TEXT_ENGINE_FAILED`，
  不写数值；BERT 资产缺失 → `ASSET_INVALID`。
- provenance：三项均为 `measured_model`。
- **在线指标仍是 MLM 代理**：`accuracy`/`f1`/`lossCv` 不是 TNEWS/CLUENER/AFQMC
  下游分数。CLUE 下游评测必须走独立的固定协议入口（见下）。

### 1.1 CLUE 固定协议（离线）

```powershell
python tools\run_text_clue_experiment.py --task tnews ^
  --ours-corpus <D_ours.jsonl> --ref-corpus <D_ref.jsonl> ^
  --train-file <task-train.jsonl> --eval-file <固定E.jsonl> ^
  --model-path .\weight\bert-base-chinese --output <结果.json>
```

- 同一 BERT 起点；D_ours/D_ref 各自做 MLM，**同 token 预算、同 seed、15% 掩码、
  80/10/10、低学习率**；随后用**同一任务 train** 训练两个任务头，在**同一固定 E**
  上评分。
- TNEWS/AFQMC 输出 accuracy/macro-F1；CLUENER 输出 entity-level precision/
  recall/F1。三项不能相加为“CLUE 总分”。
- 支持 `--ours-mlm-lr` / `--ref-mlm-lr` 记录数据特定调优；两侧不同学习率时，
  delta 含调参差异，不能只归因于数据质量。
- 数据转换：`tools/prepare_clue_text.py`；TNEWS/AFQMC test 的 `-1` 标签不能当验证集。
- 局限：没有真实业务 D_ours 时不要拿 CIFAR/CLUE 的任意子集冒充；没有同模型同协议的
  公开数值时不能写成论文 `S_ref`。

## 2. 图像（`app/engines/image.py`）

- 输入：`uri`/`input` 可为本地路径、业务资产 URL（`/api/v1/datasets/.../assets/...`）或 `http(s)`。
- `clarity`（measured_rule）：灰度 Laplacian 方差，`100*var/(var+500)`，0–100。
- `semantic`（measured_rule）：边缘密度 0.55 + 灰度熵 0.45，归一化到 0–100。
- `iou`（proxy）：原图 vs 确定性 JPEG 重编码+轻模糊的 Otsu 前景 mask IoU，0–1；不是人工标注分割 IoU。
- `accuracy`（proxy）：原图 vs 轻度增强图的 64 维颜色/边缘直方图余弦相似度 ×100；不是分类器准确率。
- baseline 为原图，candidate 为确定性增强图；`iou`/`accuracy` 两侧相同，表示处理保真度。
- 缺图/解码失败：`ASSET_MISSING`（strict）或 missing 列表（非 strict）。
- 本机虽已有 `model/clip` 和 `YOLOv8n`，但当前引擎没有读取它们；`SME_CLIP_MODEL` 仅为保留配置，
  即使设置也不会改变本节的代理口径。复制权重不等于接入模型。
- 本引擎版本为 `image-proxy-v1`；`resnet18/resnet50/mobilenet_v2` 权重仅由离线线性探针实验使用，
  在线任务不会因为权重存在就自动变成训练式评估。
- 数据集级质量协议（`app/experiments/image_protocol.py`）是独立入口，不改变上面的在线口径：
  `python tools\run_image_protocol.py --ours <D_ours> --ref <D_ref> --eval <固定E> --benchmark mlperftiny --output <json>`；
  API 为 `POST /api/v1/eval/image/protocol`。它支持 `resnet18`、`resnet50`、`mobilenet_v2`
  （`deit_tiny` 需额外 timm），默认 `full` 同预算训练，也支持 `linear_probe`；指标为
  `top1` 与 `macroF1`（0–100），只有 `measured_model` 才进入结论。
- 该协议先审计再训练：E 与 D_ours/D_ref 做精确 SHA256 和 16x16 灰度、8 向翻转/旋转归一化 average-hash
  近重复检查（256 bit，Hamming ≤ 5）；类别分布 JSD 和冻结 backbone 特征 MMD（含置换检验 p 值）作为 OOD 门槛；
  增强只进训练集，E 固定且不做测试时增强。特征 MMD 仅在加载本地预训练权重时强制，随机初始化时
  只作诊断；随机 backbone 的 `valid=false`，不能写成数据质量结论。
- pair 比对截断不是“已发现泄漏”：严格模式返回 `422 AUDIT_INCOMPLETE`，只有实际命中精确/近重复
  才返回 `LEAKAGE_DETECTED`。
  `benchmark` 只标记目标基准（MLPerf Tiny/CIFAR-10/ImageNet 子集/DataComp-CLIP），不会自动下载
  DataComp 的 38 个任务，也不把协议分数写成公开榜论文值。
- 当前限制：协议只支持分类；检测/分割未训练；没有真实业务 D_ours 时，CIFAR-10 等公开集只能做流程
  验证，不能冒充业务数据质量结论。

## 3. 语音（`app/engines/audio.py`）

- WAV 用标准库 `wave` + numpy 解码；其他容器尝试 soundfile/librosa，无则 `ASSET_MISSING`；不需要 ffmpeg CLI。
- `cer`（measured_model）：
  - 参考文本来自 `sample.transcript` 或 `sample.output`；
  - 字符级 Levenshtein 距离 / 参考字符数 ×100（NFKC、小写、只保留字母数字）；插入可使 CER 超过 100%，不裁剪；逐条保留 cerEdits/cerReferenceChars，批次按总编辑数/总参考字数汇总；
  - ASR 只从本地选择，优先级：
    1. `SME_PARAFORMER_MODEL` 指向 `weight/paraformer-zh`（FunASR `SeACoParaformer`，中文，需 `funasr` + `torchaudio`）；
    2. `SME_WHISPER_MODEL` 指向本地 whisper 目录，或 HF 缓存已有 `openai/whisper-tiny/base/small`；
  - 都没有 → 422 `ASR_ASSET_MISSING`，不联网下载、不伪造。
  - Paraformer 适配器位于 `app/engines/audio.py`，通过临时 16 kHz 单声道 WAV 调用 `AutoModel.generate`；
    未安装 `funasr` 时明确报错，不会静默换模型。
- `speakerAccuracy`（proxy）：逐句声学特征 leave-one-out 最近邻，命中=100/未命中=0；需要至少 2 个说话人且每类 ≥2 条；修复了剔除自身后索引未映射回训练子集的问题。
- `domainF1`（proxy）：同一 LOO 预测的 domain macro-F1，0–100；需要至少 2 个领域且每类 ≥2 条。
- 标签：`sample.speaker`/`parameters.speaker`、`sample.domain`/`parameters.domain`；单类别视为标签不足。
- 缺标签：`MEASUREMENTS_INCOMPLETE` 列出缺失；strict 不返回半套结果。
- 2026-11-02 已用 `weight/whisper-small`（967 MB）和 `weight/whisper-base`（281.1 MB）
  对 30 条 AISHELL-3 真实 WAV 做 CER；30 条均值分别为 27.78% / 41.59%，说明模型可运行但仍不足以
  支撑 12% 验收。交付包没有 speaker/domain 标签，严格任务按预期失败，未用伪标签补齐。
- 2026-11-04 新验证：`D:/python/python.exe` 已有 FunASR 1.4.16 与 torchaudio 2.3.1，
  Paraformer 在 AISHELL-1 临时 speaker-held-out 子集的固定 30 条上 CER=1.2876%（6/466 字）；
  同样 30 条的 Whisper-base CER=44.6352%（208/466 字）。这是两个冻结模型的诊断对照，
  不是 D_ours/D_ref 的训练收益，不能混同旧 AISHELL-3 的逐句均值。
- 单批引擎版本为 `audio-asr-v2`；baseline/candidate CER 是同一冻结预测，结果明确保留
  `comparison.qualityConclusionEligible=false`。16 kHz 重采样改为抗混叠 polyphase，
  NaN/Inf、截断 PCM、重复 ID、无效转写与 CSV/JSON 顶层音频字段均有回归覆盖。

### 3.1 训练式 ASR 协议

入口：`tools/run_audio_protocol.py`、`POST /api/v1/eval/audio/protocol`、
`AudioEvaluationOperator.run_protocol(AudioProtocolSpec(...))`；核心为
`app/experiments/audio_protocol.py`，版本 `audio-whisper-training-v1`。

- D_ours / D_ref 等条数，时长预算差默认 ≤5%；同一本地 Whisper 权重/processor 指纹，
  同 seed、超参、epoch、batch、实际训练步数；`full` 为全量微调，默认 `decoder` 冻结编码器。
- 固定 E 不参与调参或 checkpoint 选择。训练前核对 E 与两侧的 speaker、ID、解码 PCM、
  同长度增益/极性/重编码波形；泄漏与审计截断明确拒绝。不能据此声称覆盖任意裁剪或预训练污染。
- 同一 CER 归一化与 corpus 聚合；返回数据/模型哈希、loss 曲线、逐句预测、多种子均值与样本 std。
  不生成 WER 或未实现的 B-WER/U-WER；术语覆盖仍需独立词表/人工验证。
- `valid=true` 表示内置协议完成；`purpose=quality` 且 ≥3 种子只是协议层面的比较前提，
  调用方仍需保证业务候选数据、分布匹配与 E 的代表性。公开集 smoke 的质量归因标记始终为 false。
- 本轮 whisper-base、12 条训练/侧、12 条 E、1 epoch、3 seeds：matched 两侧均 18.83±0.65%；
  候选转写倒序的受控扰动为 24.11±1.42%，相对基线恶化 5.27 pp。
  full 路径另以 2 条训练/2 条 E、1 seed 验证，只验证可运行，不构成统计结论。
- ASR 协议不产生说话人准确率/领域 F1，二者不适用而非 0 分。
  复现与全部证据见 [audio_test1](../../audio_test1/REPORT.md)。

## 4. 视频（`app/engines/video.py`）

- OpenCV `VideoCapture` 解码；默认在时间轴 12 个区间中点取帧（`frameSamples` 可配 4–24），
  避开首尾黑帧/重复帧；打不开/0 帧 → `ASSET_MISSING`。
- `clarity`（measured_rule）：每帧 Laplacian 清晰度，视频分为
  `0.55*均值 + 0.30*p20 + 0.15*中位数`，防止单帧清晰掩盖整体模糊。
- `alignment`（proxy）：默认 caption（`output`/`caption`/`title`/`description`）关键词 vs
  画面亮度/饱和度/运动属性；无关键词时中性 60；有则 `30+70*matched/recognised`。
  设置 `alignmentMode=clip`（或 `SME_ALIGNMENT_MODE=clip`）时改用 `weight/clip/ViT-L-14.pt`：
  默认抽 8 帧，把 caption 按 75 token 分块，计算帧-块余弦，每帧取最佳块后对帧平均，
  并与整段截断 cosine 取较大者；再按显式 `clipCosineFloor`/`clipCosineCeiling`
  线性标定到 0–100。原关键词规则保留为回退路径。
  无字幕时 60 只表示“无证据”，不是语义对齐真值。
- `trust`（measured_rule）：来源域名规则；本地=80、白名单=100、已知短链/滥用域=40、
  未知=60；显式 `source` 优先，缺失时回退到 `input/uri`，本地文件不被误判成未知网页。
  可由 `config.trust` 覆盖。
- `safety`（measured_rule）：caption/标题暴力/违禁/武器关键词命中扣分，
  `max(0,100-20*hits)`；可由 `config.safetyPenalty`/`safetyKeywords` 覆盖。
- `integrity`（measured_rule）：`100*(0.6*decode_ratio+0.2*frame_ratio+0.2*duration_ratio)`；
  预期帧数/时长来自 `parameters.frameCount/expectedFrames`、`parameters.duration/expectedDuration`。
  容器既无帧数也无 fps 时完整性封顶 85，不能把“只读了前几帧”当完整。
- `quality`（meta，非五维契约）：启发式 `heuristic-vqa-v1`，含 sharpness/exposure/contrast/
  temporal/resolution 五维、`vqaScore`、统计量和 flags（黑帧/冻结/低光/过曝/低对比/低分辨率/闪烁）。
  这是诊断向量，不是训练好的 MOS 模型，也不替代五维 metric。
- baseline 为原始帧，candidate 为确定性降采样+模糊变体，clarity 重新测量。
- 视频没有成熟的“训练式数据评估”方案，本实现按 VQA + 分级路线，报告中必须标为代理/规则。
- 离线 `tools/run_video_vqa.py` 可对目录批量测量；提供真实逐视频 MOS 时计算
  Spearman/Pearson/Kendall；没有 MOS 时明确 `labels_missing`，不产生 SRCC/PLCC。
- 视频引擎版本：`video-vqa-v2`；语音引擎版本：`audio-asr-v2`。

## 5. 后训练 benchmark（`app/engines/benchmark.py`）

- 不训练模型。基础模型/优化模型必须在上游对每道题评分，导入 `measurements.baseline.score` 与 `measurements.candidate.score`（0–100）。
- 引擎统一校验导入并做配对描述分析；完整导入也调用此引擎，不再跳过 provenance/审计。缺分、布尔/字符串/非有限/越界或异常结构 → 422 `MEASUREMENTS_REQUIRED`，只列出实际缺失或无效的 sample/model/metric。
- 逐样本判定 `candidate.score - baseline.score >= 5`；批次均值差 ≥5；由 `app/eval/rules.py` 统一执行。
- provenance：`imported`。
- 2026-11-04 升级 `benchmark-import-v2`：`meta.analysis` 记录分差均值/中位数/样本标准差/范围、胜平负、达阈值题数、零分/满分计数、按 scene 分组及重复题组；`meta.sampleDigest` 保留排序后的题目及分数 SHA256。
- 1000 次确定性配对 bootstrap 给出平均分差 95% percentile 区间；同题两侧不拆散，seed=0 有效，行序不影响结果；单题区间/标准差为 null。区间只反映题目抽样，依赖独立代表性假设，不替代多训练种子；不参与业务接受判定。
- 重复内容检测仅为 NFKC/空白规范化的 input+output 精确重复，不是近重复/语义去重，也不是训练集泄漏审计。不自动剔除，保留现有每题等权契约。
- 算子 result.json、report.md、业务任务 JSON/Markdown 及离线 protocol.json 均保留分析。报告明确标示阈值为分差，且分差不代表训练数据质量差。
- 上游模型/prompt/裁判/评分版本及固定 E 无独立证据时始终标注 `PROTOCOL_UNVERIFIED`、`TRAINING_LEAKAGE_NOT_CHECKED`，不声称已满足训练式数据质量因果归因条件。
- 离线入口：`py -3.11 tools/run_protocol_experiment.py --type benchmark --samples SME_EVAL_BENCHMARK_001/dataset/sample/import_example.jsonl --out ../benchmark_test1/example --seed 0`；该示例是合成分数夹具，不能作为真实业务模型效果。

## 6. Demo 与实测的边界

| 场景 | 行为 |
|---|---|
| 前端预置/演示数据集 + `mode=demo` | 直接使用前端固定 measurements，不调用引擎 |
| `mode=measured` + 数据自带完整指标 | 归一化后评测，provenance=`imported` |
| `mode=measured` + 缺指标 + `measurementSource=engine` | 调用对应引擎，合并后评测 |
| `mode=measured` + 缺指标 + `measurementSource=import` | 422 `MEASUREMENTS_REQUIRED` |
| 引擎缺依赖/资产 | 422 `ENGINE_UNAVAILABLE` / `ASSET_MISSING` / `ASR_ASSET_MISSING` |
| 任何失败 | 不写 result，不伪造 0 分；任务标记 failed 或请求返回错误 |

## 7. 复现与性能

- 文本：固定 seed，CPU 500 条约数十秒（取决于 CPU）；默认 240s 超时。
- 图像：单图毫秒级；批量受解码影响。
- 语音：WAV 解码快；ASR 首次加载模型较慢，之后缓存。
