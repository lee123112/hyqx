# 小模型测评 · 接口契约（v1.0）

> 本契约以 `图像资产库 · 高质量数据平台_files/dataset-evaluation.js.下载` 为唯一前端语义来源。
> 业务 API 前缀 `/api/v1`；算子接口在根路径；统一返回 `{"code":0,"msg":"success","data":...}`。
> 错误返回 `{"code":<http>,"msg":...,"data":{"errorCode":...,"details":...}}`。

### 1.1 创建任务请求

```json
{
  "name": "文本语料质量评测",
  "type": "text",
  "mode": "demo",
  "source": {"kind": "preset"},
  "config": {"thresholds": {"accuracy": 80, "f1": 80, "lossCv": 0.2},
             "weights": [25,25,20,15,15],
             "grades": {"AA": 95, "A": 85, "B": 70}, "highValue": false},
  "baselineConfig": {"id": "demo-baseline-text-bert-base", "name": "通用文本理解对比",
                     "version": "1.0", "status": "published"},
  "modelId": "bert-base",
  "seed": 42,
  "parentId": null,
  "autoRun": true
}
```

`source.kind`：

- `preset`：使用 `DEMO-EVALUATION-<TYPE>-001` 预置数据；
- `raw` / `production`：`source.id` + 可选 `version`/`sampleHash`，服务端校验版本；
- `upload`：请求携带 `samples`，或先调用 `/datasets/import`；
- `rerun`：请求携带 `parentId`，可带 `samples` 覆盖（人工修订后的参数）。

实测模式：`measurementSource=import` 时必须有逐条指标；`engine` 时允许缺失，由运行器调用测量引擎补齐。Demo 数据集禁止创建实测任务（`DEMO_ONLY_DATASET`）。

```json
                    "mode": "demo", "version": "v1", "sampleIds": ["..."]},
  "modelId": "bert-base",
  "modelVersion": "1.0",
  "baselineConfig": {"id": "...", "name": "...", "version": "1.0"},
  "baselineModel": "公开语料基线",
  "candidateModel": "BERT-base",
  "downstreamTask": "文本分类 / 命名实体识别",
  "validationVersion": "validation-v1",
  "seed": 42,
  "planSnapshot": {"...": "完整方案快照"},
  "parameterSource": {"mode": "custom"},
  "config": {"thresholds": {}, "weights": [], "grades": {}, "highValue": false},
  "samples": ["..."],
  "logs": [{"time": "...", "message": "...", "tag": "开始"}],
  "feedback": [],
  "result": {"samples": ["..."], "summary": {"...": "..."},
             "engine": {"provenance": {}, "meta": {}, "missing": [], "notes": []}},

```

`result.engine` 只在真实调用测量引擎时出现；它保留 `engineVersion`、`seed`、训练语料/模型配置、
`missing` 和说明。只导入逐条指标的任务不会伪造该块。报告 JSON 同名字段、Markdown 的
“测量协议”小节和 `/predict` 的 `result.json` 都使用这份数据。

### 1.3 逐条指标

```json
{"samples":[
  {"id": "S001", "input": "...", "title": "...", "scene": "...",
   "sourceStep": "文本分块", "parameters": {}, "highValue": false,
   "measurements": {
     "baseline": {"accuracy": 77, "f1": 78, "lossCv": 0.18},
     "candidate": {"accuracy": 86, "f1": 87, "lossCv": 0.10}
   }}
], "meta": {"type": "text", "mode": "measured", "measurementSource": "engine"}}
```

指标范围：`iou`、`lossCv` 为 0–1；其余 0–100。实测必须 baseline/candidate 全部齐全。

### 1.4 反馈对象

```json
{
  "id": "EVAL...-F1", "taskId": "EVAL...", "sampleId": "S004",
  "issue": "准确率未达标", "sourceStep": "文本分块",
  "suggestion": "回溯文本分块和清洗参数...", "parameters": {},
  "status": "pending", "note": "", "parametersAfter": null,
  "verificationId": null, "performanceBefore": null,
  "performanceAfter": null, "createdAt": "...", "updatedAt": "..."
}
```

处理：`PATCH` body `{note, parametersAfter, verificationId?}`。指定复评任务时必须满足：子任务、已完成、同类型/模式/验证集/种子/配置/基线模型/候选模型，且该样本达标。满足则 `verified`，否则 422 `VERIFICATION_INVALID`。

## 2. 算子接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | `operatorCount=5` |
| POST | `/uploadFile?uniqueId=` | 上传数据集包 |
| POST | `/predict` | 运行算子 |
| POST/GET | `/downloadFile?uniqueId=&path=` | 下载产物 |
| POST | `/removeFile?uniqueId=&path=` | 删除产物/工作区 |

算子 ID：`SME_eval_text`、`SME_eval_image`、`SME_eval_audio`、`SME_eval_video`、`SME_eval_benchmark`。

`/predict` 请求：

```json
{
  "uniqueId": "EVAL261102ABC123",
  "operatorId": "SME_eval_text",
  "inputFile": "/workspace/EVAL261102ABC123/input/dataset.zip",
  "params": {
    "type": "text", "mode": "measured", "measurementSource": "engine",
    "config": {}, "baseline": {"planId": "demo-baseline-text-bert-base"},
    "seed": 42, "registerTask": true, "taskName": "..."
  },
  "isLastOperator": true
}
```

响应 `data`：`outputFile`（`isLastOperator=true` 时为 zip base64，否则为逻辑路径）、`outputPath`（始终为逻辑路径，供下载）、`lineageFile[]`（累计血缘记录）、`lineagePath`、`terminal`、`stopChain`、`downstream`、`gate_status`、`quality_status`、`rowsIn/rowsOut`、`report`、`result`、`logs`、`missingMetrics`。

产物：`output/result.json`、`measurements.jsonl`、`report.md`、`summary.md`、`metrics.csv`、`output.zip`、`run.log`、`lineage_<uniqueId>.jsonl`、`manifest.json`。

### 2.4 图像数据集级质量协议

`POST /api/v1/eval/image/protocol`（本地目录路径，POST 受 API Key 保护）：

```json
{
  "oursDir": "..\\dataset\\image\\ours",
  "refDir": "..\\dataset\\image\\ref",
  "evalDir": "..\\dataset\\image\\eval",
  "proxyModel": "resnet18",
  "benchmark": "mlperftiny",
  "trainingMode": "full",
  "seed": 42,
  "epochs": 10,
  "batchSize": 32,
  "imageSize": 128,
  "maxOodSamples": 256,
  "maxLeakagePairs": 4000000,
  "augment": true,
  "strict": true
}
```

返回 `data` 是完整协议记录：`protocol`、`data`、`leakage`、`ood`、`S_ours`、`S_ref`、`delta`、
`provenance`、`valid`、`conclusionEligible`。`S_*` 只含 `top1`、`macroF1`；`leakage`/`ood` 未通过时
严格模式返回 422，非严格模式返回 `valid=false` 的诊断记录。未加载本地预训练权重时 `valid=false`。
`maxLeakagePairs` 截断返回 `AUDIT_INCOMPLETE`，不是 `LEAKAGE_DETECTED`。该接口只支持
`classification`，不伪造 DataComp 38 任务结果。

## 3. 错误码

| errorCode | HTTP | 场景 |
|---|---|---|
| `REQUEST_INVALID` | 422 | 请求字段缺失/格式错误 |
| `CONFIG_INVALID` | 422 | 阈值/权重/等级非法 |
| `SAMPLE_INVALID` | 422 | 样本缺字段/ID 重复/超 5000 |
| `MEASUREMENTS_REQUIRED` | 422 | 实测模式未提供指标 |
| `MEASUREMENTS_INCOMPLETE` | 422 | 指标缺失 |
| `DEMO_ONLY_DATASET` | 422 | Demo 数据集创建实测任务 |
| `DATASET_CHANGED` | 409 | 数据集版本/哈希变化 |
| `DATASET_TYPE_MISMATCH` | 422 | 数据集与评测类型不匹配 |
| `BASELINE_UNVERIFIED` | 422 | 实测基线未发布/未验证 |
| `VERIFICATION_INVALID` | 422 | 复评条件不满足 |
| `TASK_EXISTS` | 409 | 任务 ID 已存在 |
| `JOB_RUNNING` | 409 | 重复运行 |
| `ENGINE_UNAVAILABLE` | 422 | 类型无测量引擎 |
| `ASSET_MISSING` | 422 | 媒体/模型资产缺失 |
| `ASR_ASSET_MISSING` | 422 | 语音 CER 缺 ASR |
| `BUDGET_MISMATCH` | 422 | 音频 D_ours/D_ref 条数、总时长或实际训练步数不等预算 |
| `TRANSCRIPT_INVALID` | 422 | 音频训练参考文本为空、无有效字符或超出 token 预算 |
| `TRAINING_FAILED` | 422 | ASR 训练 loss/梯度出现非有限值 |
| `INFERENCE_INCOMPLETE` | 422 | ASR 生成达到 token 上限但尚未结束 |
| `PROTOCOL_MISMATCH` | 422 | D_ours/D_ref 训练量或类别不一致 |
| `OOD_MISMATCH` | 422 | 图像协议分布审计未通过 |
| `LEAKAGE_DETECTED` | 422 | 固定评测集与训练集重复/近重复 |
| `AUDIT_INCOMPLETE` | 422 | 泄漏近重复比对达到 pair 上限，未完成全量核对 |
| `NOT_FOUND` | 404 | 资源不存在 |
| `PATH_ESCAPE` | 400 | 路径越界 |
| `PAYLOAD_TOO_LARGE` | 413 | 超限 |
| `INTERNAL_ERROR` | 500 | 未预期错误 |

## 4. 前端语义对齐（必须保持）

音频增量：`POST /api/v1/eval/audio/protocol` 接收 `oursManifest/refManifest/evalManifest/modelDir`、
`seeds`（默认 42/43/44）、`epochs`、`batchSize`、`learningRate`、`trainingMode`（decoder/full）、
`purpose`（smoke/exploration/quality）、`device`、`language`、`maxDurationGap`、`maxNewTokens`、
`maxLeakagePairs`。路径限定为本地项目/数据目录；清单内音频相对各清单解析。
响应沿用 `{code,msg,data}`，`data` 为数据集级协议结果：`protocol/data/leakage/S_ours/S_ref/delta/runs`、
`valid` 与 `qualityConclusionEligible`。此入口同步执行，不混入单批 `/predict` 的三指标阈值门禁。
完整请求 schema 以 `openapi.json` 为准；示例见音频包 README。

音频 CER 实测值允许 >100%；带完整计数时批次用 corpus CER。旧导入无计数时仍按逐句均值，
Demo 的固定响应结构保持兼容；冻结引擎的模型/归一化/计数与比较局限保存在 engine.meta。

- 任务状态：`draft / running / paused / completed / failed`。
- 评测类型：`text / image / video / audio / benchmark`。
- 模式：`demo / measured`。
- 视频等级：`AA / A / B / C`；其他类型逐样本 `passed`。
- 文本准确率/F1：候选 ≥ 阈值 **且严格高于基线**；benchmark：均值分差 ≥ 阈值。
- 视频：加权分（权重/100），`AA` 需 `config.highValue` 或样本 `highValue`；`accepted = C 级数量为 0`。可选 `config.frameSamples`（4–24，默认 12）控制每视频采样帧数；`engine.meta.videos[id].quality` 是启发式 VQA 诊断，不参与五维阈值或等级，也不是 MOS。
- 反馈：未达标样本逐条生成，`pending → processed → verified`。
- 报告：单任务报告 + 周/月/季周期报告，Demo 与实测分组。
