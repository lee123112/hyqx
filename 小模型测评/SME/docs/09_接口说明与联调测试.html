SME 接口说明与联调测试

版本：SME-2026.11.12-server。更新日期：2026年11月12日。适用人员：平台后端、前端、服务器部署与联调测试人员。

本服务提供五类数据集测评算子，以及数据集管理、评测任务、基线方案、结果报告等业务接口。工程侧调用算子时使用“上传、执行、下载、清理”四步；前端使用业务数据集与任务接口。本文给出当前交付版本的实际参数、ZIP约定、可执行命令和验收口径。

2 公共约定

2.1 鉴权

部署环境变量SME_API_KEY为空时不校验Key；设置后，下列请求带请求头：

X-API-Key: 与服务器SME_API_KEY相同的值

受保护请求是/uploadFile、/predict、/removeFile，以及/api/v1/下除GET、HEAD、OPTIONS以外的请求。只读浏览、健康检查、文档和当前下载接口不要求Key。前端在设置中填写相同Key。

Key错误时HTTP为401，响应为：

{"code":401,"msg":"缺少或错误的 X-API-Key","data":null}

2.2 请求和响应

JSON请求使用Content-Type: application/json，文件上传使用multipart/form-data。正常JSON响应为：

{"code":0,"msg":"success","data":{}}

业务错误同时返回非2xx HTTP状态和错误信封，例如：

{
  "code": 422,
  "msg": "实测模式缺少逐条指标",
  "data": {"errorCode":"MEASUREMENTS_REQUIRED","details":null}
}

下载接口成功返回文件二进制，SSE返回事件流；二者不使用普通JSON成功信封。报告接口的format=md仍返回JSON信封，data是Markdown字符串。

2.3 ID 路径和容量

  • 算子uniqueId是1至64位字符串，以英文字母或数字开头，后续允许英文字母、数字、下划线和连字符；不要传中文、空格、斜线。
  • 每次独立测试生成新的uniqueId。它隔离工作区，不提供请求幂等或重复执行保护；attempt也不提供自动去重。
  • 上传返回的inputFile和执行返回的outputPath是服务逻辑路径，必须原样回传；浏览器和工程调用方不需要读取服务器磁盘路径。
  • 默认上传文件上限200MB、普通批次样本上限5000、ZIP条目上限5000。Nginx请求上限256MB。200MB是上传文件大小限制，不是已实现的解压总量限制。
  • 输入数据ZIP不放模型权重。完整交付包中的47个模型文件保留在各算子的models/内。

2.4 执行与结果状态

POST /predict同步执行，调用方等待完成响应；训练请求应预留较长超时。包内客户端和Nginx代理使用1800秒。请求超时后不能认定服务端已停止；先核对任务和日志，再决定是否重新运行。

业务POST /api/v1/eval/tasks的autoRun=true在后台执行，创建接口返回后应查询任务状态。两种调用方式的状态不可混用。

字段 含义
HTTP 200、code=0 请求成功返回
/predict data.status=succeeded 本次算子计算和产物生成成功
业务任务status=completed 后台任务执行结束，不代表指标达标
report.accepted=true/false 普通测评批次按本次规则的业务判定
训练协议accepted=null 当前业务接受阈值未配置，结果待业务判定
qualityConclusionEligible 该证据是否具备作质量比较结论的资格，不等于自动验收通过

当前/predict成功响应中的gate_status=PASS、quality_status=PENDING为适配字段；判断质量必须读取data.report.accepted或data.result.summary.accepted。例如后训练区分度样例执行成功，但平均得分差4分低于5分，accepted=false。

方法 ZIP根文件 /predict params 计算范围

真实联调显式写mode=measured；省略mode会默认进入Demo。普通数据包不放protocol参数；protocol=false也不是普通模式开关，应直接省略这个字段。

4 工程侧算子接口

调用顺序：uploadFile → predict → downloadFile → removeFile。下载并验证产物后再清理。

4.1 上传输入

POST /uploadFile?uniqueId=IT-001，multipart字段：

参数 位置 必填 说明
uniqueId Query 是 本次调用工作区ID
file multipart 是 本次数据集ZIP或兼容清单文件

成功响应示例：

{
  "code": 0,
  "msg": "success",
  "data": {
    "inputFile": "/workspace/IT-001/input/dataset.zip",
    "fileName": "dataset.zip",
    "size": 520,
    "sha256": "文件实际SHA256"
  }
}

示例中的sha256表示动态值。inputFile必须取当前上传响应，不自行按示例拼接，也不传G:\...。

4.2 执行测评

POST /predict，JSON请求：

{
  "uniqueId": "IT-001",
  "operatorId": "SME_eval_benchmark",
  "inputFile": "/workspace/IT-001/input/dataset.zip",
  "params": {
    "mode": "measured",
    "measurementSource": "import",
    "seed": 42,
    "registerTask": true,
    "taskName": "后训练区分度接口联调"
  },
  "isLastOperator": false
}
参数 必填或默认 说明
uniqueId 必填 与本次上传一致
operatorId 必填 使用第3节的精确ID
inputFile 必填 上传响应的逻辑路径
params.mode 实测必填 measured；省略时默认demo
params.measurementSource 普通测评指定 import或engine；训练协议不需要
params.protocol 训练ZIP必填true 从ZIP查找唯一protocol.json；普通测评省略
params.seed 默认42 整数；显式指定时须与协议首个种子一致
params.config 可选 完整阈值等配置；不传则使用模态默认值
params.registerTask 建议true 将本次结果登记到前端任务列表；否则taskId可为空
params.taskName 可选 登记任务名称
isLastOperator 建议false true将输出ZIP编码成Base64放在响应中；false返回逻辑路径

训练ZIP的params示例：

{"mode":"measured","protocol":true,"registerTask":true,"taskName":"图像小预算训练联调"}

完整config结构可从GET /api/v1/eval/templates的defaultConfig[type]获取后修改。不要只假定任意一个阈值字段能在算子入口自动合并；基线页面和算子入口的配置合并逻辑不同。

/predict不通过params.baseline选择平台基线方案。工程侧若要复用方案阈值，先读基线方案，将其config传给params.config；前端业务任务使用第6节的baselineConfig。

成功响应主要字段如下，示例为节选，动态路径以实际响应为准：

{
  "code": 0,
  "msg": "success",
  "data": {
    "status": "succeeded",
    "taskId": "IT-001",
    "outputFile": "/workspace/IT-001/SME_eval_benchmark/run/output.zip",
    "outputPath": "/workspace/IT-001/SME_eval_benchmark/run/output.zip",
    "outputIsBase64": false,
    "gate_status": "PASS",
    "quality_status": "PENDING",
    "rowsIn": 2,
    "rowsOut": 2,
    "report": {"total":2,"passed":1,"issues":1,"accepted":false},
    "missingMetrics": []
  }
}

实际响应另含jobId、血缘记录、日志、耗时和结果摘要。isLastOperator=true时outputFile改为Base64，outputIsBase64=true，但outputPath仍可用于下载。

4.3 下载产物

推荐GET /downloadFile?uniqueId=...&path=...。path使用执行响应的data.outputPath，客户端必须做URL编码。也支持POST，JSON如下：

{"uniqueId":"IT-001","path":"/workspace/IT-001/SME_eval_benchmark/run/output.zip"}

下载成功为ZIP二进制。不要对成功响应调用JSON解析器。下载失败才按HTTP状态及错误信封排查。

输出ZIP通常包含result.json、manifest.json、report.md、summary.md、metrics.csv、measurements.jsonl、run.log、血缘文件和inputs/中的输入副本；训练另保留完整协议。数据集级训练不生成虚构逐条分数，逐条文件可能为空。

manifest.json记录产物文件散列。资源使用包内相对路径，私有模型使用逻辑标识；模型实体不重复复制到输出ZIP。下载后移除服务端工作区，输出包内保留的输入和协议仍可读取。

4.4 清理工作区

POST /removeFile，JSON：

{"uniqueId":"IT-001"}

不传path时清理整个本次算子工作区；传path时清理指定文件或目录。响应data包含removed列表和count。已不存在的整个工作区再次清理返回count=0。

此操作不删除算子私有模型，也不删除业务任务记录。清理后重跑需要重新上传输入；需要继续在前端查看输入或复评时先保留工作区。

5 输入 ZIP 标准

5.1 通用规则

JSON和JSONL使用UTF-8；根目录直接放主清单，不额外套一层同名目录。包内路径使用/和相对路径。普通媒体同时提供input和file，二者指向同一个资源。样本ID非空且唯一，布尔值使用JSON的true/false。

模态和运行方式由请求决定，给samples.json增加type/mode不会自动选择算子。不要把samples.json和protocol.json两类入口混在一个包中等待自动切换。

5.2 导入已有指标

dataset.zip
├─ samples.json
└─ assets/                 可选的原始媒体

文本结构示例：

{
  "samples": [
    {
      "id": "S001",
      "input": "企业发布了季度经营报告。",
      "measurements": {
        "baseline": {"accuracy":77,"f1":78,"lossCv":0.18},
        "candidate": {"accuracy":85,"f1":86,"lossCv":0.15}
      }
    }
  ]
}

每条两侧完整填写：

type 指标字段 数值单位
text accuracy、f1、lossCv 前两项0至100；lossCv为0至1
image iou、clarity、semantic、accuracy iou为0至1，其余0至100
audio cer、speakerAccuracy、domainF1 CER为非负有限百分数，可超过100；其余0至100
video clarity、alignment、trust、safety、integrity 均为0至100
benchmark score 0至100，同一道题两侧真实分数

音频每侧可另提供cerEdits和cerReferenceChars；全部样本两侧都提供完整有效计数时采用语料级CER，否则按现有逐句聚合口径。80%的准确率写80，IoU 0.85写0.85。

导入指标记录来源为imported，不核验上游训练协议。前端选定“基线方案”也不能替代样本中的measurements.baseline。

5.3 引擎测量

dataset.zip
├─ samples.json
└─ assets/
   ├─ sample-001.jpg
   └─ sample-002.jpg

图像清单示例，不带measurements：

{
  "samples": [
    {"id":"IMG001","input":"assets/sample-001.jpg","file":"assets/sample-001.jpg"},
    {"id":"IMG002","input":"assets/sample-002.jpg","file":"assets/sample-002.jpg"}
  ]
}
模态 输入与标注要求 当前测量口径
文本 input为真实文本；至少两个规范化后不同的内容组 内部划分验证集，默认使用私有BERT进行MLM代理测量，不是CLUE下游成绩
图像 可解码图片及相对路径 像素规则和处理一致性代理；不消费人工mask计算真实标注IoU
音频 音频、transcript、speaker、domain 固定ASR CER和声学特征留一代理诊断，不是两份语料分别训练Whisper
视频 可解码视频，可附caption、source、expectedDuration、expectedFrames、highValue 五维规则/代理评分；CLIP对齐须配置启用，默认是关键词规则

音频若要求三项指标完整，speaker和domain各自至少两类、每类至少两条。推荐WAV/PCM。单条示例：

{"id":"AUD001","input":"assets/A001.wav","file":"assets/A001.wav","transcript":"请打开客厅的灯。","speaker":"spk01","domain":"home","language":"zh"}

引擎两侧的含义按模态而定：图像是原图与确定性处理的比较；音频CER目前两侧相同；视频默认两侧描述同一输入。它们不能直接作为D_ours与D_ref训练收益的证据。benchmark没有现场自动答题评分流程。

5.4 训练对比协议

training.zip
├─ protocol.json
├─ ours/
├─ ref/
├─ eval/
└─ task/                   仅文本另有共同下游训练数据
模态 protocol中的路径字段 数据内容
文本 oursCorpus、refCorpus、trainFile、evalFile 两份继续预训练语料、共同下游任务训练集T、固定测试集E
图像 oursDir、refDir、evalDir 三份按类别目录组织的图片
音频 oursManifest、refManifest、evalManifest 三份JSONL清单和对应本地音频

图像protocol.json示例：

{
  "protocol": {
    "oursDir": "ours",
    "refDir": "ref",
    "evalDir": "eval",
    "proxyModel": "resnet18",
    "trainingMode": "full",
    "epochs": 1,
    "batchSize": 4,
    "seeds": [42],
    "purpose": "exploration"
  }
}

图像每份数据结构如ours/cat/O001.jpg、ours/dog/O002.jpg，三个集合至少两类、类别名一致，ours/ref每类条数相同。当前比较分类top1/macroF1，不是分割训练。

文本语料JSONL每行{"id":"O001","text":"真实语料"}；下游TNEWS每行{"id":"T001","text":"新闻内容","label":0}。可选任务为tnews、afqmc、cluener，其字段见输入规范。两侧先分别继续预训练，再共用T训练下游任务，最终在同一E测试。

音频清单每行如下，audio相对当前清单解析：

{"id":"O001","audio":"audio/O001.wav","text":"请打开客厅的灯。","speaker":"train-spk01"}

音频两侧训练条数一致，总时长默认差距不超过5%；E与训练两侧的说话人和音频独立，单条0.05至30秒。当前协议训练Whisper并比较CER。

训练ZIP省略modelPath/modelWeight/modelDir，默认读取所属算子私有模型。E不能参与训练、调参或模型选择。小预算样例均为单种子exploration；quality至少三个种子，formal至少五个种子，并须通过相应审计，仍需业务接受标准。

6 前端业务接口

6.1 推荐调用顺序

  1. GET /api/v1/eval/templates获取模态、modelProfiles、defaultConfig。
  2. GET /api/v1/eval/baselines?type=image获取方案；选择同type/modelId/mode、已published或verified的方案。
  3. POST /api/v1/datasets/import上传普通ZIP，得到数据集id、version、sampleHash。
  4. POST /api/v1/eval/tasks创建任务；autoRun=true立即后台执行，false保存草稿。
  5. 查询任务详情或接收SSE，等待completed/failed。
  6. 读取结果、报告，按需复核和复评。

6.2 普通数据集导入

POST /api/v1/datasets/import，multipart字段：

字段 必填 值
file 是 samples清单ZIP或兼容文件
type 是 text/image/audio/video/benchmark
mode 建议指定 已有指标measured；引擎原始数据unmeasured；演示demo
name 否 数据集展示名

注意：unmeasured是数据集导入状态；执行引擎测量时创建的任务仍为mode=measured。

成功data是已登记数据集对象，常用字段为id、name、type、mode、count、version、sampleHash、samples。媒体引用转换为/api/v1/datasets/.../assets/...形式，前端按返回URI展示。

6.3 创建普通测评任务

POST /api/v1/eval/tasks。下例动态ID、version、sampleHash须替换为刚导入的数据；示例内置图像方案ID来自当前交付快照，实际前端仍应动态查询：

{
  "name": "图像引擎联调",
  "type": "image",
  "mode": "measured",
  "source": {
    "kind": "raw",
    "id": "刚导入返回的数据集ID",
    "version": "刚导入返回的version",
    "sampleHash": "刚导入返回的sampleHash"
  },
  "modelId": "image-validator",
  "baselineConfig": {"id":"CFG261106MVC6HY"},
  "measurementSource": "engine",
  "seed": 42,
  "autoRun": true
}

本版本内置且带证据的方案会按id从服务端重新读取；通用前端建议将选中基线对象完整传入baselineConfig，尤其是自定义方案，不能只伪造status。指定自己的config时保留完整规则，表示使用自定义参数。

已有指标任务将measurementSource改为import，数据集导入使用measured，其余流程相同。source.version/sampleHash是可选并发校验字段；传入后与当前数据不一致会返回409 DATASET_CHANGED。

modelId是前端档案标识，不等于磁盘模型路径：text为bert-base，image为image-validator，video为video-quality，audio为cnn-lstm或small-transformer，benchmark为benchmark-pair。页面模型名称不保证现场运行了同名算法，实际实现以结果engine和训练协议记录为准。

6.4 任务状态 日志和报告

方法和路径 用途
GET /api/v1/eval/tasks/{taskId} 完整任务，读取status、error、result.summary
POST /api/v1/eval/tasks/{taskId}/run 启动草稿或可重启任务，已完成任务不能直接再次run
GET /api/v1/eval/tasks/{taskId}/logs?after=0 增量日志；响应items、lastSeq，下一轮after用lastSeq
GET /api/v1/eval/tasks/{taskId}/events SSE，事件status、log、done；单连接约300秒后结束，长任务重连或轮询
GET /api/v1/eval/tasks/{taskId}/report?format=json JSON信封，data为报告对象
GET /api/v1/eval/tasks/{taskId}/report?format=md JSON信封，data为Markdown字符串
POST /api/v1/eval/tasks/{taskId}/pause 请求暂停
POST /api/v1/eval/tasks/{taskId}/resume 恢复已暂停任务
POST /api/v1/eval/tasks/{taskId}/rerun 创建复评子任务，可传autoRun和修改内容

任务状态为draft/running/paused/completed/failed。暂停控制在任务流程步骤之间生效，不是训练batch级检查点，也不保证立即打断正在执行的模型计算。报告要求任务已完成。

6.5 训练任务入口

当前前端训练表单提交服务器路径对象，例如：

  "type": "image",
  "mode": "measured",
  "seed": 42,
  "protocol": {
    "oursDir": "/app/dataset/business/image/ours",

这些路径必须在后端容器中存在。业务任务的相对路径以SME上级项目目录为准；为了部署清晰，表单使用容器业务数据绝对路径。前端表单当前未自动完成训练ZIP上传解包；若输入是训练ZIP，使用第4节uploadFile/predict流程。不要把protocol=true直接提交给业务tasks接口，它要求协议对象。

6.6 基线方案

前端基线方案保存阈值、版本、模型档案等信息，不会自动建立D_ref/E，不会自动训练模型。measurements.baseline则是每条实际参考分数，两者职责不同。

自定义后训练区分度判定方案示例：

{
  "name": "后训练区分度联调方案",
  "type": "benchmark",
  "modelId": "benchmark-pair",
  "mode": "measured",
  "status": "published",
  "version": "1.0",
  "seed": 42,
  "config": {"thresholds":{"score":5}}
}

提交到POST /api/v1/eval/baselines后，使用返回对象创建任务。published表示方案可选，不代表已在新服务器完成真实模型实验。内置方案不可修改或删除。

8.2 从外部机器执行

在有完整SME样例目录的机器上，使用Python3.11，无须额外安装HTTP客户端库：

启用Key时填写真实值。需要下载后自动清理时另加--cleanup。脚本全部成功返回0，任一用例失败返回1。

报告位于runtime/manual_tests/run-*/summary.json，或--output指定目录；每例包含response.json、case-summary.json，下载时包含output.zip。若要在前端继续查看输入或复评，不加--cleanup。

9 curl完整调用示例

这一段可整体复制到SME根目录执行，依赖curl和Python3。默认调用后训练区分度导入样例，成功下载后清理。修改BASE_URL和SME_API_KEY适配服务器；动态路径由响应提取，不需要手工拼接。

set -eu
BASE_URL="${BASE_URL:-http://127.0.0.1:17024}"
SME_API_KEY="${SME_API_KEY:-}"
PYTHON="${PYTHON:-python3}"
export UNIQUE_ID="IT-$("$PYTHON" -c 'import uuid; print(uuid.uuid4().hex)')"
mkdir -p "runtime/curl-tests/$UNIQUE_ID"
export TEST_OUT="runtime/curl-tests/$UNIQUE_ID"

curl -sS --max-time 120 -H "X-API-Key: $SME_API_KEY" \
  -F 'file=@examples/input_zips/导入已有指标/后训练区分度_2条.zip;filename=dataset.zip' \
  "$BASE_URL/uploadFile?uniqueId=$UNIQUE_ID" -o "$TEST_OUT/upload.json"

"$PYTHON" - <<'PY'
import json, os, pathlib
folder = pathlib.Path(os.environ['TEST_OUT'])
upload = json.loads((folder / 'upload.json').read_text(encoding='utf-8'))
assert upload['code'] == 0, upload
payload = {
    'uniqueId': os.environ['UNIQUE_ID'],
    'operatorId': 'SME_eval_benchmark',
    'inputFile': upload['data']['inputFile'],
    'params': {'mode': 'measured', 'measurementSource': 'import', 'registerTask': True},
    'isLastOperator': False
}
(folder / 'predict.json').write_text(json.dumps(payload), encoding='utf-8')
PY

curl -sS --max-time 1800 -H "X-API-Key: $SME_API_KEY" \
  -H 'Content-Type: application/json' --data-binary "@$TEST_OUT/predict.json" \
  "$BASE_URL/predict" -o "$TEST_OUT/response.json"

"$PYTHON" - <<'PY'
import json, os, pathlib
folder = pathlib.Path(os.environ['TEST_OUT'])
response = json.loads((folder / 'response.json').read_text(encoding='utf-8'))
assert response['code'] == 0, response
result = response['data']
assert result['status'] == 'succeeded', result
assert result['rowsIn'] == result['rowsOut'] == 2, result
assert result['report']['accepted'] is False, result
download = {'uniqueId': os.environ['UNIQUE_ID'], 'path': result['outputPath']}
(folder / 'download.json').write_text(json.dumps(download), encoding='utf-8')
(folder / 'remove.json').write_text(json.dumps({'uniqueId': os.environ['UNIQUE_ID']}), encoding='utf-8')
PY

curl -sS --max-time 120 -H "X-API-Key: $SME_API_KEY" \
  -H 'Content-Type: application/json' --data-binary "@$TEST_OUT/download.json" \
  "$BASE_URL/downloadFile" -o "$TEST_OUT/output.zip"

"$PYTHON" - <<'PY'
import hashlib, json, os, pathlib, zipfile
folder = pathlib.Path(os.environ['TEST_OUT'])
with zipfile.ZipFile(folder / 'output.zip') as archive:
    assert archive.testzip() is None
    manifest = json.loads(archive.read('manifest.json'))
    for item in manifest['files']:
        assert hashlib.sha256(archive.read(item['name'])).hexdigest() == item['sha256']
print('Downloaded output ZIP verified')
PY

curl -sS -H "X-API-Key: $SME_API_KEY" -H 'Content-Type: application/json' \
  --data-binary "@$TEST_OUT/remove.json" "$BASE_URL/removeFile" -o "$TEST_OUT/remove-response.json"

"$PYTHON" - <<'PY'
import json, os, pathlib, zipfile
folder = pathlib.Path(os.environ['TEST_OUT'])
removed = json.loads((folder / 'remove-response.json').read_text(encoding='utf-8'))
assert removed['code'] == 0, removed
with zipfile.ZipFile(folder / 'output.zip') as archive:
    assert archive.testzip() is None
print('Call passed; quality accepted=false is expected for this fixture')
PY

该样例baseline均分65、candidate均分69、变化4；默认分差阈值5，因此接口通过且业务未达标是预期结果。切换其他方法优先使用第8节工具，避免手工同时修改算子ID、ZIP和params。

11 异常和业务流程测试

所有写入测试使用新ID和联调数据，不对正在运行的业务任务执行清理。

用例 操作 预期
N01 鉴权 启用Key后不带Key调用predict HTTP401，data=null
N02 非法ID 上传时uniqueId含斜线或空格 HTTP400，INVALID_UNIQUE_ID
N03 未知算子 正常ID，operatorId为未注册值 HTTP422，UNKNOWN_OPERATOR
N04 模态不匹配 图像算子params.type=text HTTP422，OPERATOR_TYPE_MISMATCH
N05 缺指标 不带measurements的文本样本，选择import HTTP422，MEASUREMENTS_REQUIRED
N06 缺媒体 图像清单引用包中不存在的文件，选择engine HTTP422，ASSET_MISSING
N07 不支持的训练类型 video使用protocol=true和有效协议ZIP HTTP422，CONFIG_INVALID
N08 下载不存在文件 正常ID，path指向不存在文件 HTTP404，NOT_FOUND
N09 重复清理 同一工作区成功清理后再清理 HTTP200、code=0、count=0
N10 Demo误当实测 measured任务使用preset来源 HTTP422，DEMO_ONLY_DATASET
N11 报告时机 获取尚未完成的草稿任务报告 HTTP422，REQUEST_INVALID
N12 未发布方案 以draft状态基线对象创建measured任务 HTTP422，BASELINE_UNVERIFIED
B01 指标导入业务链 业务导入benchmark ZIP，选匹配方案，创建/启动任务 completed；summary.accepted=false且分差4
B02 引擎业务链 导入image unmeasured，创建engine任务 completed，保留引擎审计与样本结果
B03 媒体展示 按业务导入返回的uri读取媒体 HTTP200，可解码媒体；不使用宿主绝对路径
B04 日志与报告 读取logs、report(json/md)、已完成任务events 日志游标可用；md位于JSON data；SSE有done

固定E泄漏、训练量不匹配、ZIP大小/条数上限、真实服务器重启和浏览器页面流程，还应在目标数据及部署环境中验证。它们不因12个小样本通过就自动获得正式验收结论。

12 常见错误处理

HTTP或errorCode 处理建议
401 核对前端设置或X-API-Key与服务器一致
INVALID_UNIQUE_ID 按第2节生成合法新ID
UNKNOWN_OPERATOR 使用精确operatorId，检查health注册数
REQUEST_INVALID / CONFIG_INVALID 检查字段类型、布尔值、未知协议字段、配置范围
DATASET_INVALID 检查根清单、合法JSON、UTF-8和ZIP完整性
MEASUREMENTS_REQUIRED / MEASUREMENTS_INCOMPLETE 导入方式补齐每条两侧指标，或改用正确引擎包
MODEL_ASSET_MISSING / ASR_ASSET_MISSING 运行models、environment，核对私有模型与依赖
ASSET_MISSING 检查媒体文件、相对路径、解码器或容器挂载路径
DATASET_CHANGED 重新读取数据集version/sampleHash再创建任务
BASELINE_UNVERIFIED / BASELINE_MISMATCH 选择已发布且匹配模态、模型档案和mode的方案
BUDGET_MISMATCH / PROTOCOL_MISMATCH 核对两侧训练条数、类别数量、时长与训练预算
LEAKAGE_DETECTED / OOD_MISMATCH 核对固定E独立性、近重复和数据分布，不通过改ID绕过
AUDIT_INCOMPLETE 审计达到比对上限，不能解释为审计通过
NOT_FOUND 检查ID、资源路径、是否已清理；先区分任务与算子工作区
PAYLOAD_TOO_LARGE / HTTP413 对照后端与Nginx限制；Nginx拒绝时响应可能是HTML，不是JSON
500 保存响应、任务ID、对应日志后定位；不要将未完成请求误报为指标不达标
