# 审查修复与训练协议接入

2026-11-04 修复后的接口说明。旧测试目录中的历史分数与报告保留原样；新版本结果应重新运行后产生，不能把旧分数标注为新版本证据。

2026-11-11模型封装修订：文本、图像、音频训练协议可以省略模型路径，由所属算子内部models目录解析；数据ZIP不再绑定开发机器SME/weight路径。显式提供模型路径仍属于可选高级覆写。

## 公共入口与兼容路径

ZIP 的根目录清单、带顶层目录清单及相对媒体路径均通过同一工作区解析。`/workspace/...` 映射至配置的工作区且禁止越界。原来的本地绝对路径输入继续支持。视频顶层描述、来源和预期时长/帧数在规范化后保留。

每次执行使用时间戳加 UUID 的独立运行目录；同秒重跑和并发不会覆盖旧产物。完整指标导入保留 `imported` 来源、样本数、seed 和上游协议未核验说明；`seed=0` 在算子、业务任务及登记后保持一致。非法 seed 返回错误，不静默改成42。

登记后的引擎任务复跑会清除旧测量值后重新测量，不把训练内诊断转成导入指标。普通任务与训练协议任务相互切换时重建来源、模式和方案元数据，并替换当前反馈批次；正在运行的任务不能被重新登记覆盖。

文本在线仍是 MLM 代理。输入按 NFKC 与去空白后的内容组划分训练/验证，比例按内容组近似90/10，组内所有重复文本归属同侧。JSON 保留所有诊断分数，正式汇总与反馈只使用 `engine.meta.evaluation.sampleIds`；训练内分数在 `result.diagnostics.trainingSamples`。少于两个独立内容组时返回 `EVALUATION_INVALID`，不能构造独立验证集合。MLM 结果不具备训练式数据质量结论资格。

视频引擎为 `video-vqa-v3`：五维分数、quality 诊断及 MOS 预测都评价输入原视频。兼容字段 baseline/candidate 均为同输入诊断，不能解释为训练收益。只有配置 `degradationDiagnostic=true` 时才进行人工退化，诊断进入 meta 而不参与正式评分或分级。安全分仅为文本关键词规则，未做画面安全模型评估；缺少匹配 MOS 时仍不产生 SRCC/PLCC。

## 训练协议接入四接口

文本、图像、音频均可以显式经 `/predict` 运行训练协议，未指定 `params.protocol` 时继续使用原来的兼容测量入口。

先上传 `protocol.json`，文件内容为 `{"protocol": {...}}`，然后请求：

```json
{
  "uniqueId": "TRAINING-DEMO-001",
  "operatorId": "SME_eval_image",
  "params": {
    "mode": "measured",
    "protocol": true,
    "registerTask": true
  },
  "isLastOperator": true
}
```

也可直接将协议对象放入 `params.protocol`。`protocol=true` 支持 JSON 配置，或包含唯一 `protocol.json` 及数据文件的 ZIP。相对路径以该配置文件目录为准；`params.protocol` 直接提供对象时以上传输入目录为准。路径限定于项目数据、配置运行目录和工作区，越界会拒绝。

图像协议对象示例（需要真实类别目录，路径须自行填写）：

```json
{
  "oursDir": "ours",
  "refDir": "ref",
  "evalDir": "eval",
  "proxyModel": "resnet18",
  "benchmark": "cifar10",
  "trainingMode": "full",
  "epochs": 3,
  "batchSize": 32,
  "seeds": [42, 43, 44],
  "purpose": "quality"
}
```

文本需要 `oursCorpus/refCorpus/trainFile/evalFile/task`；缺省使用 `SME_EVAL_TEXT_001/models/bert-base-chinese`，可选设置 `modelPath/tokenizerPath` 覆写。task 为 tnews/afqmc/cluener，其他参数采用 TextProtocolSpec 的驼峰名称（如 mlmSteps、mlmTokenBudget）。音频需要 `oursManifest/refManifest/evalManifest`；缺省使用 `SME_EVAL_AUDIO_001/models/whisper-base`，可选设置 `modelDir` 覆写。图像缺省按proxyModel选取 `SME_EVAL_IMAGE_001/models` 下对应权重，可选设置modelWeight。部署时复制各算子models资产，不需要公共weight挂载。也接受对应Python snake_case字段名，但同一字段不得同时使用两种名称。未知字段与类型错误返回422。

产物保留 `result.json`、`protocol.json`、报告、血缘、清单及 ZIP。`protocol.json` 是完整协议结果，包含数据指纹、两侧指标、训练配置与统计。未实现逐条质量指标的训练协议将 `measurements.jsonl` 留空，明确是数据集级结果，不给每条输入虚构分数。`registerTask=true` 将协议及结果登记为可查询任务，保存解析后的路径，供复跑使用。

## 业务任务与报告

`POST /api/v1/eval/tasks` 支持无需 samples 的训练协议任务：

```json
{
  "name": "图像训练协议评测",
  "type": "image",
  "mode": "measured",
  "protocol": {
    "oursDir": "image_test1/data/matched/ours",
    "refDir": "image_test1/data/matched/ref",
    "evalDir": "image_test1/data/matched/eval",
    "epochs": 3,
    "seeds": [42, 43, 44],
    "purpose": "quality"
  },
  "autoRun": true
}
```

业务任务路径相对 `小模型测评` 目录，任务支持运行、完成/失败状态、JSON/Markdown 报告和 rerun。重跑默认继承协议；不生成不适用于数据集级比较的逐条反馈。

草稿创建不加载模型或训练资产；完整协议字段、路径及数据审计在运行时校验。草稿成功保存不代表协议已通过校验。周期报告通过 scopeTaskCounts 区分逐样本与数据集级任务，训练协议的 sampleCount 按固定 E 的评测数量统计，趋势记录明确 scope。

训练协议结果使用 `summary.scope=dataset`，完整记录位于 `result.trainingProtocol`。`qualityConclusionEligible` 仅表示内置协议与重复实验条件具备，不能证明样本代表性或业务质量已达标。未配置业务接受标准时，`summary.accepted=null`，报告为“探索结果”或“协议比较有效，待业务判定”，不能把执行成功直接解释成数据质量合格。

## 多种子、泄漏和训练诊断

- 文本、图像支持 `seeds` 与 `purpose=exploration/quality/formal`。单次探索仍可使用 seed；quality 至少3种子，formal至少5种子。两侧每个种子配对训练，输出 runs 与 statistics 的均值、样本 std 和 n；单种子 std=null。图像还保留实际更新步数及逐 epoch/step loss，NaN/Inf 明确失败。
- 音频维持已有配对多种子协议；新增 formal 至少5种子门槛，CER 使用 corpus 聚合。原有 smoke/exploration 结果不自动升级为质量结论。
- 文本离线在训练前检查任务 train/E、D_ours/E、D_ref/E 的规范化内容重复；相同内容更换 ID 不能绕过。AFQMC 同时审计句对及 MLM 语料中的句子成分。审计是规范化内容重复检测，不覆盖语义改写。
- 图像仍需通过精确/近重复与 OOD 审计且使用本地预训练权重。单种子即便 valid=true，也不能标为 conclusionEligible=true；图像随机权重流程测试 valid=false。
- 不同文本 MLM 学习率会保留调参差异说明并阻止单独归因于数据质量。
- 新旧 text/image/audio 训练入口与在线文本训练共用进程内可重入锁，避免并发重设全局随机种子；文本、图像跨种子运行的数据指纹必须一致，否则拒绝汇总。

真实业务数据代表性、公开基线协议对应、视频真实 MOS 和 benchmark 上游逐题评分协议仍需要独立证据。此次代码修复没有制造这些验收结果。
