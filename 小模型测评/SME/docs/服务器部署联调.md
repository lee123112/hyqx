# 服务器部署与联调

交付版本：SME-2026.11.12-server。对外入口容器 **op-pre-eva**，端口 **17024**。后端内部容器 **op-pre-eva-backend**，在Compose网络内监听6289；外部只需要访问17024。

## 1. 上传与解压

上传外层的 `SME_deploy_20261112.zip` 和 `SHA256SUMS.txt`。Linux服务器示例：

```sh
mkdir -p /opt/op-pre-eva
cd /opt/op-pre-eva
# 将两个文件上传到当前目录后执行
sha256sum -c SHA256SUMS.txt
unzip SME_deploy_20261112.zip
cd SME
python3 tools/verify_package.py
```

交付ZIP包含唯一的SME顶层目录。`verify_package.py`校验交付清单中的文件大小和SHA-256，包含全部模型；退出码0、status=passed表示匹配。创建.env、产生runtime数据后仍可校验，校验器不会删除或覆盖任何数据。

默认部署需要Linux x86_64、Docker及Compose v2。Python运行时为3.11，随Docker镜像构建；宿主Python只用于解压后的文件校验。模型已包含，Docker镜像与Python wheel没有离线打包。首次构建须能访问镜像源、系统包源和Python包源。

## 2. 配置与启动

```sh
cp -n .env.example .env
# 如需Key或内网包源，先编辑.env；端口SME_HTTP_PORT默认17024
sh tools/deploy.sh check
sh tools/deploy.sh up
```

`up`不会覆盖已有.env，会构建后端、启动两容器，并等待健康检查。后续启动或更新可再次运行同一命令。

| 项目 | 默认值或位置 |
|---|---|
| 对外容器 | op-pre-eva |
| 对外端口 | 17024，映射入口容器80 |
| 内部后端 | op-pre-eva-backend:6289，不发布宿主端口 |
| 页面 | http://服务器IP:17024 |
| 健康检查 | http://服务器IP:17024/health |
| OpenAPI文档 | http://服务器IP:17024/docs |
| 业务API | http://服务器IP:17024/api/v1/... |
| 算子API | 同端口下的/uploadFile、/predict、/downloadFile、/removeFile |
| 数据持久化 | 宿主runtime → 后端/app/data |
| 业务训练数据 | 宿主dataset/business → 后端/app/dataset/business，只读 |

CPU是默认构建方式，torch与torchvision从CPU wheel源成对安装；默认单个后台任务、4个CPU计算线程。更大的正式训练需按任务规模调整资源和训练预算。本交付没有开启GPU容器运行配置。

.env可配置SME_API_KEY、SME_MAX_UPLOAD_MB、SME_MAX_WORKERS、SME_TEXT_TIMEOUT_SECONDS、OMP_NUM_THREADS、MKL_NUM_THREADS。依赖源为PIP_INDEX_URL与TORCH_INDEX_URL；自建源须同时具备匹配的torch/torchvision wheel。Nginx请求上限为256MB，后端上传文件上限默认200MB，改变后者时同步检查deploy/nginx.conf。

启用SME_API_KEY后，页面设置中填同一个Key；外部写接口使用X-API-Key请求头。健康检查和只读浏览不要求Key。默认空Key用于联调。

## 3. 启动后核验

```sh
sh tools/deploy.sh status
curl http://127.0.0.1:17024/health
sh tools/deploy.sh environment
sh tools/deploy.sh models
```

健康检查应返回code=0、data.operatorCount=5。environment校验依赖版本、NumPy/Scikit-learn等二进制模块及BERT/Whisper类导入；models校验47个私有模型文件的大小与SHA-256。这些通过后再运行真实样例。

```sh
# 快速检查：已有分数导入 + 产物下载
sh tools/deploy.sh smoke --case import-benchmark --download
# 图像原始数据引擎测量
sh tools/deploy.sh smoke --case engine-image --download
# 单独运行训练协议
sh tools/deploy.sh smoke --case training-text --download
# 全部12例，下载并校验产物，成功后清理各算子工作区
sh tools/deploy.sh smoke --all --download --cleanup
```

报告保存在宿主runtime/manual_tests/run-*/summary.json；每例含response.json、case-summary.json，指定下载时另有output.zip。--cleanup隐含下载：只有产物保存并通过CRC/成员散列核验后才调用removeFile。数据库中的任务记录保留；清理过的工作区不能直接用于原任务重跑，需要重新上传。

也可在另一台机器用Python3.11执行tools/run_example.py，无需安装第三方HTTP库：

```sh
export SME_API_KEY='填写服务器配置的Key，未启用时不设置'
python tools/run_example.py --url http://服务器IP:17024 --all --download --output ./sme-check
```

如果未启用Key，不执行上面的export行。脚本成功返回0，任一用例失败返回1；不以业务指标“达标”作为接口跑通条件。

## 4. 前端联调与三种ZIP

| 方法 | 主清单 | 包中数据 |
|---|---|---|
| 导入已有指标 | samples.json | 每条measurements.baseline/candidate完整指标，可附媒体 |
| 引擎测量 | samples.json | 原始样本/媒体及必要标签，不预填measurements |
| 训练对比协议 | protocol.json | D_ours、D_ref、固定E；文本另有共同下游训练集T |

样例在examples/input_zips的三个中文子目录，索引与散列在examples/index.json。训练ZIP均已去掉开发机模型绝对路径，模型默认读取所属算子的models。

普通前端上传用于前两种方法。当前训练表单使用服务器路径：先把业务数据上传到dataset/business，再在表单填写容器路径/app/dataset/business/...；不能填写浏览器本机G盘路径。训练ZIP则通过uploadFile后调用predict，params使用mode=measured、protocol=true。两个入口不能混用。

前端的“评测基线”是阈值/版本方案，不会自动补齐导入ZIP的baseline指标，也不自动生成训练用D_ref/E。当前图像普通引擎与音频部分指标含代理诊断；训练结果是数据集级比较。单种子小预算样例是exploration，accepted=null不等于运行失败。

## 5. 运维与排查

```sh
sh tools/deploy.sh logs -f backend
sh tools/deploy.sh logs frontend
sh tools/deploy.sh down
```

down保留宿主runtime和dataset。更新前备份已有.env、runtime、dataset/business；不要用新包的空目录覆盖业务数据。固定容器名要求同一Docker主机只运行这一套，另一套须修改名称和端口。

| 现象 | 检查位置 |
|---|---|
| 构建下载失败 | 镜像源、apt源、.env中的两个Python包源；这是联网依赖，不是缺少模型 |
| 页面打不开 | op-pre-eva状态、17024端口映射及服务器网络放通情况 |
| 页面有了但API失败 | 从同一个17024端口访问/health，查看backend与frontend日志 |
| 401 | 前端设置/请求头中的X-API-Key是否与.env一致 |
| numpy.dtype size changed | 运行environment；用独立环境重装requirements，避免复用不兼容的旧环境 |
| MODEL_ASSET_MISSING | 运行models，核对传输是否漏掉models大文件 |
| ASSET_MISSING | 清单相对路径、真实媒体可解码性或容器业务数据路径 |
| 训练协议422 | D_ours/D_ref/E标签、数量、独立性及协议字段，查看返回的errorCode |

## 6. 裸机后端备选

```sh
python3.11 -m venv .venv
. .venv/bin/activate
python -m pip install 'torch>=2.2' 'torchvision>=0.17' --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements.txt
python -B tools/check_environment.py
sh tools/start_backend.sh
```

默认后端端口17024；仅启动后端时不会提供Vue页面。需要裸机Nginx时，让Nginx监听17024、托管frontend/dist，后端以SME_PORT=6289启动，并将deploy/nginx.conf中的backend:6289改为127.0.0.1:6289。

部署配置依据[Docker Compose up文档](https://docs.docker.com/reference/cli/docker/compose/up/)和[PyTorch安装文档](https://pytorch.org/get-started/locally/)。本机构建环境无Docker/WSL，实际本机验证与服务器待验范围见交付验收.json；配置检查不能替代服务器上的容器启动验收。
