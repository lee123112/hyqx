## 1. 固定部署参数

- 容器名：`op-speech-adversarial`。
- 服务器对外端口：`17023`；容器内端口：`8000`。
- 11 个算子共用一个 HTTP 服务和 `/predict`，不分别启动 11 个容器。
- 数据目录未随包交付；服务器首次部署时新建 `data` 并赋予容器 UID 1000 写权限。

首次启动命令及目录布局见 [README](README.md)，详细维护步骤见 [服务器部署说明](服务器部署说明.md)。

保留 11 个算子的处理代码、各自 YAML 配置、11 号 PDF 模块、公共运行库、字段契约、5 个必需噪声 WAV、部署文件与接口文档。

原 `AVP` 开发源包保留，完整测试、原型、演示数据和本地 ASR 工具可在源包中查阅，不随本部署包上传。

## 3. 六个服务接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/health` | 无信封探活，核对 `status=1`、`operators=11` |
| GET | `/operators` | 算子注册与 `paramsSpec` |
| POST | `/uploadFile?uniqueId=...` | multipart 上传，字段为 `file` |
| POST | `/predict` | 按 `operator` 调用算子 |
| GET | `/downloadFile?path=...` | 下载服务器返回路径对应的单文件字节流 |
| POST | `/removeFile?uniqueId=...` | 删除该任务全部文件，归档且不再引用后执行 |

算子业务 `code` 为数值 `0/1`；已联调平台的成功 `code` 是字符串 `"0000"`，两者分开处理。
先判断 HTTP/网络错误，再判断业务信封。`code=0`、`status=partial` 表示部分完成，需根据业务结果决定下一步。

## 4. 产物与平台配置

上传后使用响应的 `data.inputFile`。同任务内串行调用，依赖上一步产物时原样传回 `/data/...`，不要将调用方的本地盘符路径传给远端算子。
后端累积保存中间血缘记录，将累计列表传给下一步；阶段末响应为列表。不同阶段按各自输入契约整理数据。

业务后端 `SPEECH_ADV_OPERATOR_BASE` 指向 `http://<算子服务器IP>:17023`，`SPEECH_ADV_OP_RUNTIME_DIR` 指向实际可读的共享运行目录。跨主机时需先完成共享存储挂载。
音频和 PDF 只返回文件路径，文件下载及试听由业务后端提供；前端继续访问业务后端 `/hs-api/speech-adversarial/...`。
