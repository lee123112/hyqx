# 语音加扰算子服务器部署说明

> 2026-11-13 接口更新：现提供六个接口。工程侧下载采用 `GET /downloadFile?path=完整返回路径`，成功响应为文件流；先重建新版入口，再重新上传并使用本轮 outputs 路径串联。详细步骤见 [下载与远程链路修复说明](docs/downloadFile与远程链路修复-2026-11-13.md)。

更新日期：2026-11-12。部署目录为服务器上的 op-speech-adversarial 包根；本文不包含平台前后端和业务数据库的部署。

## 1. 部署参数

| 项目 | 配置 |
|---|---|
| 容器名 | `op-speech-adversarial` |
| 镜像名 | `audio-adversarial-pipeline:v1.0.0` |
| Compose 服务名 | `avp`（执行 `docker compose logs avp` 时使用） |
| 服务器对外端口 | `17023` |
| 容器内端口 | `8000`，映射为 `17023:8000` |
| 调用基址 | `http://<算子服务器IP>:17023` |
| 数据持久化 | 包根 `./data` → 容器 `/data` |
| 运行身份 | 容器 UID/GID `1000:1000` |
| 接口 | `/health`、`/operators`、`/uploadFile`、`/predict`、`/downloadFile`、`/removeFile` |

11 个算子都使用同一个地址，通过 `/predict` 请求体的 `operator` 选择。容器内的健康检查仍访问 `127.0.0.1:8000`。服务器 IP 尚未指定，交付时由部署人员填写；不使用客户端电脑的 `127.0.0.1` 代替服务器地址。

## 2. 构建与启动

服务器需已安装并启动 Docker Engine，且支持 `docker compose`。以下命令适用于 Linux Bash，在复制到服务器的 op-speech-adversarial 包根执行。

```bash
cd /opt/op-speech-adversarial  # 按实际上传目录调整
docker version
docker compose version

# bind mount 会覆盖镜像内 /data 的属主，首次部署需准备可写目录。
mkdir -p data
sudo chown 1000:1000 data
sudo chmod 750 data

# 检查配置后后台构建、启动。
docker compose config
docker compose up -d --build
docker compose ps
docker logs --tail 100 op-speech-adversarial
```

若迁移已有数据，部署前先备份，再确认已有文件及子目录对 UID 1000 可读写；上面的 `chown` 仅处理数据根目录。业务后端读共享目录时，也需授予其服务账号读取文件、进入子目录的权限。

构建阶段需要访问基础镜像仓库、系统包源及 Python 包源；运行阶段不下载模型或安装依赖。`weight/assets/` 下的 5 个 WAV 素材必须随包保留并构建进镜像；公共 `weight/models/` 与备用素材已从部署包剔除；本包只保留 `weight/assets/` 下的运行必需素材。服务器调用方需能通过防火墙/网络策略访问 TCP `17023`。

### 离线服务器

先在与目标服务器 CPU 架构一致的联网 Docker 环境构建、导出：

```bash
docker compose build avp
docker save -o op-speech-adversarial-v1.0.0.tar audio-adversarial-pipeline:v1.0.0
```

将镜像归档与 `docker-compose.yml` 复制到目标服务器，在目标部署目录准备好 `data` 及属主后执行：

```bash
docker load -i op-speech-adversarial-v1.0.0.tar
docker compose config
docker compose up -d --no-build
```

## 3. 服务器与调用方验收

先在算子服务器本机检查：

```bash
curl --fail --show-error http://127.0.0.1:17023/health
curl --fail --show-error http://127.0.0.1:17023/operators
docker inspect --format '{{.State.Health.Status}}' op-speech-adversarial
docker port op-speech-adversarial 8000/tcp
```

预期 `/health` 的 `status=1`、`operators=11`、`dataRoot=/data`；`/operators` 的 `code=0`、`data.count=11`；容器健康状态最终为 `healthy`，端口映射包含 `17023`。冷启动时可暂为 `starting`。

再从业务后端所在机器访问 `http://<算子服务器IP>:17023/health` 和 `/operators`，确认网络可达。6 接口真实 HTTP 冒烟可在安装了 Python 3 的调用机执行，输入 ZIP 内需含音频和同名 UTF-8 `.txt`：

```bash
python3 tools/http_smoke.py --base-url http://127.0.0.1:17023 --input corpus.zip
```

从另一台机器验收时，将 `--base-url` 改为算子服务器地址。脚本创建独立任务，依次验证上传、01 入库、02 标准化、血缘接续和删除；成功后删除自己的任务目录。如需排查保留产物，增加 `--keep`，脚本会输出该任务的 `uniqueId`。这项检查覆盖 01→02；其余算子的业务验收见后端接口说明及各算子 `dataset/DATA_SCHEMA.md`。开发期样本和完整链路工具保留在原 AVP 源包，本部署包不携带样本数据。

## 4. 业务后端连接方式

本节介绍原共享存储读取模式。工程侧使用 HTTP 文件回传时，按 [downloadFile 与远程链路说明](docs/downloadFile与远程链路修复-2026-11-13.md) 调用 GET + path，并按本轮返回路径串联；该模式不要求仅为产物读取额外挂载共享目录。

已联调 Java 平台使用以下配置；这些环境变量设置在**业务后端进程/容器**，不是算子容器：

```bash
export SPEECH_ADV_OPERATOR_BASE='http://<算子服务器IP>:17023'
export SPEECH_ADV_OP_RUNTIME_DIR='/srv/avp-runtime'
```

`SPEECH_ADV_OP_RUNTIME_DIR` 必须是业务后端能够实际访问的算子数据目录。按部署位置选择：

| 业务后端位置 | HTTP 地址 | 产物读取条件 |
|---|---|---|
| 与算子同一服务器，后端为本机进程 | `http://127.0.0.1:17023` | 可将运行根目录配置为 `/opt/op-speech-adversarial/data`，按实际部署路径调整 |
| 同一 Docker 网络中的后端容器 | `http://op-speech-adversarial:8000` | 后端也需挂载相同数据目录，例如挂到 `/srv/avp-runtime`；两个容器必须加入同一网络 |
| 业务后端在另一台服务器 | `http://<算子服务器IP>:17023` | 通过 NFS 等共享存储将同一份数据挂到业务后端的 `/srv/avp-runtime`；确认文件可见及读取权限 |

容器内 `127.0.0.1` 指该容器自身。前端不使用上表的容器 DNS 名；该名称只用于同一 Docker 网络的服务间调用。

例如算子返回 `/data/task_001/tmp/011/011_report.pdf`，业务后端应读取：

```text
/srv/avp-runtime/task_001/tmp/011/011_report.pdf
```

替换的只是路径开头 `/data/`。输入传回算子时仍用原始 `/data/...`，不要换成后端的挂载路径。仅修改 HTTP 地址、未共享文件目录时，探活可能成功，但入库结果读取、音频试听和报告下载仍无法完成。新版支持 GET downloadFile 并只传完整 path；业务后端已使用 HTTP 下载时，可不依赖共享目录读取。仍使用本地文件读取实现时，须保留同一份共享数据挂载。

后端连接超时建议 `10s`，算子请求读取超时建议 `1800s`（当前 Java 配置）；长任务由业务后端异步编排，页面轮询业务状态。同一个 `uniqueId` 内串行执行；不同任务使用不同 ID。网络超时后先核对已有任务与文件状态，避免直接并发重试覆盖输出。

## 5. 前端接入

推荐链路：浏览器 → 业务后端 `/hs-api/speech-adversarial/...` → 算子服务器 `:17023`。

- 本地 Vite 的 `VITE_API_PROXY_TARGET` 指向业务后端，例如 `http://127.0.0.1:8090`；不填算子地址。该变量用于开发代理，正式静态部署由网关/反向代理转发 `/hs-api` 到业务后端。
- 音频、PDF、ZIP 的下载/试听 URL 由业务后端提供，`/data/...` 不是浏览器 URL。
- 算子未配置浏览器 CORS 中间件。前端直连异域算子会受跨域限制，应经业务后端接入。
- 算子业务信封使用数值 `code=0/1`、`msg`；已联调平台使用字符串 `code="0000"` 表示成功及 `message` 字段，前端按所连接的接口判断。

详细字段、页面映射与验收清单见 [接口文档-前端联调](接口文档-前端联调.md)。外部评测算力不在此镜像中；07 接收评测结果，外部评测任务地址仍由业务后端单独配置。

## 6. 日志、维护与回退

```bash
# 日志与状态
docker compose logs --tail 200 -f avp
docker inspect --format '{{json .State.Health}}' op-speech-adversarial

# 重启或停机（保留 ./data）
docker compose restart avp
docker compose stop avp

# 已停机后重新启动
docker compose up -d
```

升级前先暂停业务后端发起新任务，等现有请求结束，再停止容器并备份数据和当前镜像：

```bash
docker compose stop avp
tar -czf ../avp-data-backup.tgz data
docker tag audio-adversarial-pipeline:v1.0.0 audio-adversarial-pipeline:rollback
# 放入新的代码/配置后重新构建。
docker compose up -d --build
```

如需回退镜像，先停止新任务和容器，再恢复旧标签；是否恢复数据由业务方依据备份与任务状态决定：

```bash
docker compose stop avp
docker tag audio-adversarial-pipeline:rollback audio-adversarial-pipeline:v1.0.0
docker compose up -d --no-build --force-recreate
```

`./data` 独立于容器生命周期。调用 `/removeFile` 会删除指定任务的上传文件与全部产物，需在归档且不再被下游引用后执行。

| 现象 | 检查项 |
|---|---|
| Restarting 且日志为 Unknown level: 'info' | 将 Compose 的 LOG_LEVEL 改为 INFO 并重新创建容器；详见 [日志级别修复说明](docs/启动日志级别修复-2026-11-13.md) |
| 容器名冲突或 `17023` 被占用 | 检查已有容器和端口占用，确认旧实例及新实例的迁移安排 |
| 本机可探活、远端不可达 | 核对服务器 IP、端口映射、防火墙及调用方网络 |
| 上传/预测出现权限错误 | 检查宿主机 `data` 对 UID 1000 的写权限与磁盘空间 |
| 后端报产物不存在 | 检查共享目录是否挂载了同一份数据、运行根目录及文件读取权限 |
| 噪声加扰报素材缺失 | 检查构建上下文的 `weight/assets`，以及维度值对应的 WAV |
| HTTP 200 但任务失败 | 检查算子响应 `code`、`msg` 和 `logs`；不能仅凭 HTTP 200 判断成功 |
| 空库打开数据资产页报 `missing_file` | 10 算子需数据集或入库记录；先完成素材入库，再统计 |
