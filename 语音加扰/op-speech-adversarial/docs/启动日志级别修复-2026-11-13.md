# 容器日志级别启动故障修复

日期：2026-11-13。适用容器：`op-speech-adversarial`，对外端口 `17023`。

## 原因

服务器日志显示容器为 `Restarting (1)`，Python 在 `logging.basicConfig()` 处抛出 `ValueError: Unknown level: 'info'`。
旧 Compose 传入 `LOG_LEVEL=info`，Python 标准日志级别字符串区分大小写，导致 HTTP 服务启动前就退出。

## 已部署服务器的即时恢复

在当前服务器部署目录执行，保留配置备份并重新创建容器；这次只变更环境变量，无需重建镜像：

```bash
sed -i.bak 's/LOG_LEVEL: info/LOG_LEVEL: INFO/' docker-compose.yml
docker compose up -d --no-build --force-recreate avp
sleep 5
curl --fail --show-error http://127.0.0.1:17023/health
docker logs --tail 50 op-speech-adversarial
```

预期探活 `status=1`、`operators=11`；日志出现服务监听 `0.0.0.0:8000`。
`docker restart` 不会更新已创建容器的环境变量，因此必须使用 Compose 重新创建容器。
若仍有报错，请检查新日志；本修复仅针对已确认的日志级别异常。

## 本地交付文件修复

- 源包与精简部署包的 Compose 默认值统一为 `LOG_LEVEL: INFO`。
- 两份 `inference.py` 均先将日志级别转为大写后传给 Python logging；Uvicorn 继续使用其要求的小写值。
- 精简包不加入测试代码、模型、data 或缓存；回归测试保留在源包。
- 上传 ZIP、SHA-256 与部署包清单同步更新。

## 验证

修复前本地 Python 3.9.7 使用 `LOG_LEVEL=info` 复现与服务器相同的启动异常；新增回归测试修复前为 3 失败、3 通过。
修复后运行源包 `test_startup.py` 和 `test_api.py`，结果为 `19 passed in 11.45s`。

分别以 `LOG_LEVEL=info`、`LOG_LEVEL=INFO` 从实际精简包启动临时 HTTP 服务，两次均通过：
探活、11 算子注册、上传、01 入库、02 标准化及任务删除。临时服务和数据已清理。
本机没有 Docker，未实际构建镜像，亦未修改远端服务器。
