## 1. 部署与启动

服务器统一基址：`http://<算子服务器IP>:17023`。11 个算子均使用这个基址的 `/predict`，请求体用 `operator` 选择算子。实际 IP 由部署人员提供。

```bash
# 服务器交付：先按部署说明准备 data 权限，再后台构建启动。
docker compose up -d --build

# 无 Docker 的开发环境：显式使用 17023；不传 --port 时 CLI 仍默认 8000。
python inference.py --serve --host 0.0.0.0 --port 17023
```

| 项 | 值 |
|---|---|
| 服务器对外端口 | **17023**（`docker-compose.yml` 映射 `17023:8000`） |
| 容器内监听 | 8000 |
| 容器名 | `op-speech-adversarial` |
| 探活 | `GET /health` |
| 数据根目录 | `/data`（容器内）；宿主机挂载 `./data:/data` |
| 环境变量 | `AVP_DATA_ROOT`（Docker 中为 `/data`；直接运行默认包根 `data/`）、`LOG_LEVEL`（默认 `info`） |
| 运行时网络 | **不需要**（不联网、不下载模型、不 pip install） |

`map.json` 的 `server.listenPort` 和每个算子的 `port` 均为 `17023`，表示同一个对外服务端口；不为单个算子额外开放端口。部署、离线镜像交付及维护命令见 [服务器部署说明](服务器部署说明.md)。

### 1.1 已联调 Java 平台配置

在业务后端设置 `SPEECH_ADV_OPERATOR_BASE=http://<算子服务器IP>:17023`，
`SPEECH_ADV_OP_RUNTIME_DIR=/srv/avp-runtime`（以真实挂载路径为准）。后者必须能读取算子服务器 `./data` 的同一份文件；不同服务器通过共享存储挂载。若后端就在同一宿主机运行，可将该变量直接配置为 AVP 的 `data` 绝对路径。

同一 Docker 网络内，业务后端容器也可用 `http://op-speech-adversarial:8000`，但仍需挂载数据目录。容器内 `127.0.0.1` 不会指向其他容器。完整拓扑和路径换算见 [服务器部署说明 §4](服务器部署说明.md#4-业务后端连接方式)。

连接超时建议 10 秒，读取超时建议 1800 秒；当前 Java 平台已配置这两个值。前端请求长任务时由业务后端异步执行，页面轮询业务状态。

### 1.2 上传与预测示例

以下 Bash 命令可在调用方执行。先将 `OPERATOR_BASE` 换为实际服务器地址；`corpus.zip` 内含音频和同名 UTF-8 `.txt`。

```bash
export OPERATOR_BASE='http://<算子服务器IP>:17023'
curl --fail --show-error "$OPERATOR_BASE/health"
curl --fail --show-error "$OPERATOR_BASE/operators"
curl --fail --show-error -X POST "$OPERATOR_BASE/uploadFile?uniqueId=server_demo_001" \
  -F 'file=@corpus.zip'
```

上传成功后，将 `data.inputFile` 原样写入下列请求的 `inputFile`。示例是 ZIP 解压时的返回路径；实际以响应为准。再次独立试验时换一个新的 `uniqueId`，避免覆盖已有产物。

```bash
cat > ingest.json <<'JSON'
{
  "operator": "avp_ingest_corpus",
  "uniqueId": "server_demo_001",
  "inputFile": "/data/server_demo_001/input/extracted",
  "isLastOperator": false,
  "params": {
    "dataset_name": "服务器链路联调",
    "source": "自主采集",
    "manifest_mode": "none"
  }
}
JSON
curl --fail --show-error --max-time 1800 -X POST "$OPERATOR_BASE/predict" \
  -H 'Content-Type: application/json' --data-binary @ingest.json
```

确认 HTTP 请求成功后仍需检查 JSON 的 `code`。`code=0` 时，下一步 02 使用本次返回的 `data.lineageFile.outputFile` 作为 `inputFile`，
将当前记录加入累计 `lineageFile` 列表；02 参数示例为 `{"sample_rate":16000,"channels":1,"format":"wav_pcm16","min_duration":2,"max_duration":10}`。
可用 [HTTP 冒烟脚本](tools/http_smoke.py) 自动演示动态取路径、01→02 接续和任务清理：

```bash
python3 tools/http_smoke.py --base-url "$OPERATOR_BASE" --input corpus.zip
```

### 1.3 平台接口与算子接口的边界

算子服务不带 `/hs-api` 前缀；`/hs-api/speech-adversarial/...` 属于现有 Java 业务后端。算子成功信封是数值 `code=0`、`msg="success"`，业务后端成功信封是字符串 `code="0000"`、`message="SUCCESS"`。浏览器使用业务后端接口及其文件下载 URL，不直接访问算子 `/data/...`。

## 2. 接口总览

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/health` | 探活 |
| `GET` | `/operators` | 11 个算子注册表 + 每个算子的 `paramsSpec`（**前端可用它生成表单**） |
| `POST` | `/uploadFile?uniqueId=` | 上传 zip / 单文件 |
| `POST` | `/predict` | 调用指定算子 |
| `GET` | `/downloadFile?path=` | 按完整返回路径获取文件流，兼容 POST JSON |
| `POST` | `/removeFile?uniqueId=` | 删除该任务在容器内的目录 |

现提供 `GET /downloadFile?path=完整路径` 文件流接口，兼容 filePath/inputFile 与 POST JSON。工程侧不必单独传 uniqueId/operatorId。
产物通过 `data.outputs` / `data.outputFile` 里的**容器内路径**返回，平台侧按路径读取；
具体怎么把它变成可下载 URL，见 §4.7。

11 的报告默认 `format=all`，一次出 `011_report.md` / `011_report.html` / `011_report.pdf` 三件，
三份同源同数；`data.outputFile.main` 固定是 **`report_md`**（报告中心按 main 打开正文），PDF 只作下载件。

## 3. 统一响应信封

```json
{ "code": 0, "msg": "success", "data": { }, "logs": ["..."] }
```

| 字段 | 说明 |
|---|---|
| `code` | `0` 成功 / `1` 失败。**判成败只看 `code`，不要看 HTTP 状态码** |
| `msg` | 成功固定 `success`；失败形如 `invalid_params: dataset_name 不能为空` |
| `data` | 业务载荷，见各接口 |
| `logs` | `/predict` 执行过程的日志行数组；上传、删除及请求校验失败等响应可能不带，调用方按空数组兼容 |

### 3.1 HTTP 状态码约定

| 场景 | 状态码 |
|---|---|
| 业务成功 | 200 |
| 业务失败（参数非法、解码失败、版本不存在…） | **200**（`code=1`） |
| 未知算子、缺 `uniqueId`、`params` 非对象等 | 400 |
| 上传缺少必填 multipart `file` | 422（FastAPI 校验结构 `detail`，不是业务信封） |

业务处理捕获的未预期异常会转成 200 + `code=1` + `msg` 前缀 `internal_error:`。调用方仍需先处理 HTTP 非 2xx、网络超时或网关错误，再解析业务信封；不能假定所有返回都带 `code`。

## 4. 接口详解

### 4.1 `GET /health`

```json
{ "status": 1, "service": "audio-adversarial-pipeline", "version": "v1.0.0", "operators": 11, "dataRoot": "/data" }
```

### 4.2 `GET /operators`

前端做「选择算子 / 渲染参数表单」时调它，**不要在前端硬编码参数**。

```json
{
  "code": 0,
  "data": {
    "count": 11,
    "operators": [
      {
        "directory": "AVP_INGEST_AUD_001",
        "number": 1,
        "operatorId": "avp_ingest_corpus",
        "name": "语料入库匹配校验",
        "tag": "语料入库",
        "stage": "样本生产",
        "stageId": "S1",
        "stagePosition": "1/6",
        "isLastOfStage": false,
        "summary": "把音频与参考文本清单配对成带 uttid 的语料数据集…",
        "outputs": { "corpus": "001_corpus.jsonl", "rejects": "…", "report": "…" },
        "paramsSpec": {
          "dataset_name": { "type": "string", "required": true, "desc": "…", "example": "…" },
          "source": { "type": "enum", "required": true, "values": ["自主采集", "公开采购", "合作方提供", "业务回流"] }
        }
      }
    ]
  }
}
```

`paramsSpec` 的 `type` 取：`string` / `int` / `float` / `bool` / `enum` / `string[]` / `float[2]` / `object[]` / `object` / `int|int[]`。
`required=true` 的字段前端必须标红星；`default` 有值就预填；`desc` 放说明；`example` 可做占位符。
**规格里没有 `min` / `max` 字段**，数值边界写在 `desc` 文案里（如「2–50 字」）。

> 11 个算子合计 71 个参数项，前端写一个通用的 `paramsSpec → 表单` 渲染器即可，不要逐个算子手写。

### 4.3 `POST /uploadFile?uniqueId={id}`

`multipart/form-data`，字段名 `file`。

```
POST /uploadFile?uniqueId=task_20261102_001
Content-Type: multipart/form-data
file=<zip 或单个音频/清单>
```

响应：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "uniqueId": "task_20261102_001",
    "inputFile": "/data/task_20261102_001/input/extracted",
    "archive": "/data/task_20261102_001/input/pkg.zip",
    "bytes": 1048576,
    "workDir": "/data/task_20261102_001"
  }
}
```

要点：

- 上传 **zip 会自动安全解压**（保留目录结构、防路径穿越、限 20 万条目 / 20 GiB），
  `inputFile` 返回**解压目录**；
- 上传**单文件**则 `inputFile` 是该文件路径；
- `uniqueId` 规则：字母数字 `._-`，其它字符会被替换成 `_`，最长 128；
- 同一 `uniqueId` 重复上传会覆盖同名文件，**建议每个任务一个唯一 id**。

### 4.4 `POST /predict`

```json
{
  "operator": "AVP_PERTURB_AUD_003",
  "uniqueId": "task_20261102_001",
  "isLastOperator": false,
  "inputFile": "/data/task_20261102_001/tmp/002/002_std.jsonl",
  "lineageFile": { },
  "params": { "dimension": "noise", "values": ["白噪"], "snr_db": [5, 15] }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `operator` | ✅ | 接受目录名 `AVP_PERTURB_AUD_003` / `operatorId` `avp_mix_noise` / `tag` `噪声混音` / 编号 `3`（大小写不敏感） |
| `uniqueId` | ✅ | 同上传时的 id |
| `isLastOperator` | ❌ | 是否**阶段最后一个**算子，默认 `false` |
| `inputFile` | ❌ | 推荐显式传上传返回的路径；后续按上一步血缘的 `outputFile` 或该算子的输入契约接续 |
| `lineageFile` | ❌ | 后端累积保存的血缘记录列表；当前算子会在传入历史上追加记录 |
| `params` | ❌ | 业务参数，字段见 `/operators` 或 §6；也允许把参数平铺在请求体顶层 |

**省略 `inputFile` 的条件**：所需文件已经上传到当前任务。服务只会在 `/data/{uniqueId}/input/` 下找解压目录或唯一输入文件，不会自动寻找其他任务或业务库的文件。

响应：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "operator": "avp_mix_noise",
    "operatorDirectory": "AVP_PERTURB_AUD_003",
    "name": "噪声混音加扰",
    "version": "v1.0.0",
    "status": "success",
    "statistics": { "input": 120, "output": 240, "snr_error_avg_db": 0.001 },
    "outputs": { "batch": "/data/.../tmp/003/003_batch.jsonl" },
    "result": { },
    "lineageFile": { "operator": "avp_mix_noise", "outputFile": "/data/.../tmp/003/003_batch.jsonl", "…": "…" },
    "outputFile": { }
  },
  "logs": ["[2026-11-02 14:03:41] 开始执行算子：噪声混音加扰", "…"]
}
```

`status` 取值：`success` / `partial` / `failed`。**`partial` 时 `code` 仍是 0**，
前端要渲染成「部分完成」（黄色），不要渲染成失败。

### 4.5 阶段编排：`isLastOperator` 与血缘（最容易做错，请照做）

```
阶段第一个算子      显式传上传返回的 inputFile；isLastOperator 按阶段及动作决定
   ↓ 返回 data.lineageFile.outputFile   ← 传给下一个算子的 inputFile
阶段中间算子        isLastOperator=false,  inputFile=上一算子的 lineageFile.outputFile
   ↓
阶段最后一个算子    isLastOperator=true,   inputFile=上一算子的 lineageFile.outputFile
   ↓ 返回 data.outputFile（阶段最终产物的文件对象 + 小文本内联内容）
     返回 data.lineageFile（本阶段完整血缘列表）
```

- **中间算子**：`data.lineageFile` 是**对象**（含 `outputFile` 临时路径），轻量；
- **阶段末算子**：`data.lineageFile` 是**列表**（本阶段全部血缘），并且额外给
  `data.outputFile = { main, files: {name:{path,bytes,sha256}}, content: {name: "文本内容"} }`。
  `content` 只对 ≤512 KB 的文本类产物（`.json/.jsonl/.md/.html/.txt/.csv/.tsv`）内联。

中间响应仅包含当前记录，后端需累积各条记录，把累计列表作为下一步请求的 `lineageFile`，阶段末才会返回完整列表。
仅原样转发上一条记录时，后续仍可运行，但更早的历史不会自动恢复。阶段末响应已经是列表时，以该列表更新已保存的历史，避免重复追加；
后续输入路径取列表最后一条记录的 `outputFile`，或按业务契约显式选择 `data.outputs` 中的输入产物。

#### 路径约定（务必看）

服务返回的所有路径都是**容器内约定路径**，形如 `/data/{uniqueId}/tmp/003/003_batch.jsonl`。

| 场景 | 怎么做 |
|---|---|
| 传给下一个算子当 `inputFile` | **原样回传即可**，服务自己会把 `/data/...` 反解回真实目录 |
| 平台后端要读文件 | 把 `/data/` 换成自己的挂载根目录（compose 里是宿主机 `./data`） |
| 前端展示 | 原样展示即可，**不要**当 URL 打开 |

跨主机时，挂载根必须来自算子服务器的共享数据，不能是调用方本地新建的空目录。请求中的 `inputFile` 也不能填写调用方 Windows 盘符路径；先上传，或使用算子容器实际可访问的路径。数据目录读取权限与共享存储配置见服务器部署说明。

> 这个反向映射是必须成对出现的：服务既能吐 `/data/...`，就必须能把它收回来。
> 早期版本只做了单向映射，导致「按契约回传上一算子的 `outputFile`」直接报
> `missing_file` —— 已修复，`tools/run_chain_demo.py` 就是拿这条路径真跑通 16 步的。

### 4.6 `POST /removeFile?uniqueId={id}`

```json
{ "code": 0, "msg": "success", "data": { "removed": "/data/task_20261102_001" } }
```

递归删除该任务目录（含上传、中间产物、输出）。**不可恢复**，前端务必二次确认。

### 4.7 产物怎么变成可下载 / 可播放的 URL（必读）

算子通过 downloadFile 读取其返回的 `/data/...` 单文件。业务后端可按 path 下载到自己的存储，再提供带业务权限的试听、预览和下载 URL：

| 场景 | 平台要做的 |
|---|---|
| 前端播放音频 | 起一个静态/下载接口（或反代），把 `/data/...` 路径映射成 URL，再交给 `<audio>` |
| 下载报告 PDF | 同上；`outputs.report_pdf` 或 `outputFile.files.report_pdf.path` 都能拿到路径 |
| 报告 HTML 里的「下载 PDF」按钮 | 见下方三种方案 |

**方案 A（推荐）**：平台已有文件下载接口（如 `/api/file/download?path=`），前端把路径丢给它。
**方案 B**：同源反代，把数据根目录挂成 `/files/`，浏览器直接访问 `/files/{uniqueId}/tmp/011/011_report.pdf`。
**方案 C**：报告预览也从 `/files/.../011_report.html` 打开，HTML 里的相对链接 `href="011_report.pdf"` 自然生效。

报告 HTML 页脚的按钮长这样，前端可以用锚点替换成平台地址：

```html
<a class="btn-dl" href="011_report.pdf" download
   data-report-pdf="011_report.pdf" data-report-no="RPT-BENCH-20261104-001">下载 PDF</a>
```

> **坑**：如果用 `iframe srcdoc` 内联渲染 HTML，相对路径会以当前页面 URL 为基准 → 404。
> 要内联预览就选方案 A/B 替换 `href`，否则用方案 C 直接打开文件。
> `format` 不含 `pdf` 时按钮不渲染，不会留死链。

路径规则回顾（与 §4.5 一致）：

- 服务返回的 `/data/...` 是**容器内约定路径**，传给下一个算子时原样回传；
- 平台后端读文件时把 `/data/` 换成宿主机挂载根（compose 里是 `./data`）；
- 前端**不要**把 `/data/...` 当 URL 打开。

## 5. 五个阶段与调用顺序

| 阶段 | 名称 | 算子链 | 阶段末算子 |
|---|---|---|---|
| **S1** | 样本生产 | 01 入库 → 02 标准化 → 03 噪声混音 / 04 语速变换 → 05 质检 → 06 版本 | `AVP_VERSION_DATA_006` |
| **S2** | 评测执行 | 07 评测结果接收 | `AVP_EVAL_DATA_007` |
| **S3** | 效果分析 | 08 差异归因 → 09 优化建议 | `AVP_ADVICE_DATA_009` |
| **S4** | 数据运营 | 10 数据资产统计 | `AVP_ASSET_DATA_010` |
| **S5** | 报告中心 | 11 优化建议报告 | `AVP_REPORT_DATA_011` |

**S1 注意**：03 与 04 是**并列的加扰维度**（可以只跑一个，也可以都跑），
两者的输出都是「批次表」，都作为 05 质检的输入。若都跑，05 需分别质检两批后再合并。

**05 是两段式**，必须调两次：

```
第 1 次：{ "mode": "start" }     → 出待复核队列 005_review_queue.jsonl，结论「待复核」
        （前端渲染人工试听页面，用 data.outputs.review_queue 的样本列表）
第 2 次：{ "mode": "finalize", "review_decisions": [
            { "sample_id": "S0001", "decision": "pass" },
            { "sample_id": "S0002", "decision": "reject" }
          ] }
        → 出 005_batch_final.jsonl + 005_qc_final.json
```

复核未判定完就提交 → `code=1` + `msg` 前缀 `human_review_incomplete`。

**两个状态口子（前端别踩）**

1. `mode=start` 出「待复核」时，`status` 是 **`partial`** 而不是 `success`
   —— 人工还没听完，这批不算走完，`code` 仍是 0。前端此时应禁用「下一步/发布」，
   直到 finalize 出「通过」。
2. 加扰批次（03/04 的产物）的 `snr_threshold_db` **要按混音目标区间设**。
   03 的目标是 `snr_db=[5,15]`，若仍用原始语料的 `15 dB` 判存疑，会把整批故意加噪的
   样本全判成「存疑」进而 `不通过`（实测 `snr_below_ratio=1.0`）。建议取低于混音下限的值
   （如 `3.0`），只拦真正的异常样本。
3. **语速维度不做 SNR 判定**。04 的产物没加噪声，SNR 没有业务含义，配置项
   `qc.no_snr_dimensions: ["speed"]` 里的维度：
   - 队列与报告里 `snr_source` 记 **`not_applicable`**、`snr_db` 为 `null`、`snr_below=false`；
   - `checks.snr.below_ratio` 的**分母只算可测样本**（`checks.snr.applicable`），
     否则 888 条语速样本会把噪声样本低于阈值的占比稀释成假通过；
   - `data.statistics` 新增 `snr_applicable` / `snr_not_applicable` 两个计数。
   前端展示时对 `not_applicable` 的样本应当显示「不适用」，**不要**渲染成 0 dB 或「合格」。

**03/04 返回 `partial` 是正常的**：全静音样本无法按目标 SNR 混音，会被记入
`rejected` 并在 rejects 里说明，其余样本照常产出。`partial` 表示「部分样本被跳过」，
**不代表整批失败**，产物可直接给 05 用。

## 10. 已知坑（已经踩过，写下来省你们时间）

1. **不要用 HTTP 状态码判断业务成败**：参数非法也是 200，只有信封坏了才 400。
2. **`partial` 不是失败**：`code=0` + `status=partial`，表示部分样本被跳过，产物仍然可用。
3. **`inputFile` 是容器内路径**，不是 URL，不能直接用浏览器打开。
4. **文件名含中文/空格**：上传时 `filename` 保留原样，但 `uniqueId` 会被清洗成安全字符。
5. **同一 `uniqueId` 并发调两个算子会互相覆盖** `tmp/{编号}/` 子目录 —— 一个任务串行跑。
6. **`/removeFile` 不可恢复**，删的是整个 `/data/{uniqueId}`。
7. 单算子 CLI 冒烟在 Windows/PowerShell 下**用 `--params-file`**，
   `--params '{...}'` 的双引号会被 shell 吃掉（已实测）。
