## 1. 三十秒结论

1. **算子服务**提供 6 个接口：`/health`、`/operators`、`/uploadFile`、`/predict`、`/downloadFile`、`/removeFile`；业务后端另有数据集、任务、下载等平台接口。
2. **11 个算子都走同一个 `/predict`**，用 `operator` 字段路由；单维度完整链最少 12 次调用（demo 跑了 16 次）。
3. 表单**不要硬编码**：参数规格从 `/operators` 的 `paramsSpec` 动态生成。
4. 判成败只看 `code`（0/1）；`status=partial` 是**部分完成**，不是失败。
5. 文件（PDF、音频）**不内联、不给 URL**，只有 `/data/...` 路径——下载/试听必须由你们后端代理。
6. 报告中心（11）的详情页字段已按原型对齐，字段映射见 §6。

## 2. 从服务器接入真服务

算子统一基址是 `http://<算子服务器IP>:17023`，容器名 `op-speech-adversarial`，容器内监听 `8000`。部署步骤见 [服务器部署说明](服务器部署说明.md)。所有算子都经同一 `/predict` 路由。

部署人员可先在算子服务器本机检查；从其他机器检查时将 `127.0.0.1` 改成实际服务器地址：

```bash
curl http://127.0.0.1:17023/health
curl http://127.0.0.1:17023/operators
```

### 2.1 已联调 Vue/Java 平台

调用链为浏览器 → 业务后端 `/hs-api/speech-adversarial/...` → 算子服务器 `:17023`。

| 配置位置 | 配置 |
|---|---|
| 业务后端 | `SPEECH_ADV_OPERATOR_BASE=http://<算子服务器IP>:17023` |
| 业务后端 | `SPEECH_ADV_OP_RUNTIME_DIR` 指向实际可读的算子数据共享目录 |
| 前端本地 Vite | `VITE_API_PROXY_TARGET=http://<业务后端IP>:8090`，指向业务后端 |
| 正式前端静态站点 | 网关将 `/hs-api` 转发到业务后端；Vite 开发代理配置不作用于构建后的静态文件 |

例：业务后端在本机 `8090`，启动前端时设置：

```powershell
$env:VITE_API_PROXY_TARGET = 'http://127.0.0.1:8090'
npm run dev -- --host 127.0.0.1
```

算子端未启用浏览器 CORS 中间件，页面通过业务后端进行上传、长任务编排与下载。业务后端跨服务器读取产物的共享目录配置见 [服务器部署说明 §4](服务器部署说明.md#4-业务后端连接方式)。

### 2.2 两套响应信封

本文后续列出的 6 接口字段属于算子契约。已联调平台前端实际连接的是业务后端，成功响应为 `code="0000"`、`message="SUCCESS"`；算子服务成功响应为数值 `code=0`、`msg="success"`。不要将两者的判断逻辑混用。

数据集、任务和报告列表由业务后端提供；算子没有查询任务进度的接口。页面轮询业务后端状态，音频/报告下载使用业务后端生成的 URL，不能拼接成 `http://<算子服务器IP>:17023/data/...`。

## 3. 统一信封与判成败

```json
{ "code": 0, "msg": "success", "data": { }, "logs": ["[2026-11-04 12:10:17] [开始] 开始执行算子：…"] }
```

| 字段 | 怎么用 |
|---|---|
| `code` | **唯一成败依据**：`0` 成功 / `1` 失败（业务失败也返回 HTTP 200） |
| `msg` | 成功固定 `success`；失败是 `前缀: 中文说明`，按**前缀**分支（§9） |
| `data` | 业务载荷，见 §4 |
| `logs` | 处理过程日志行，直接渲染到「处理过程」面板（§8） |

`data.status` 三态：`success` / `partial`（部分完成，黄色）/ `failed`（一般不会出现，失败基本都是 `code=1`）。

> 算子 `/health` **不带信封**，返回 `{status:1, service, version, operators, dataRoot}`。业务后端自己的健康接口仍使用平台信封。先处理 HTTP/网络错误，再判断业务 `code`；缺少上传字段 `file` 时会返回 HTTP 422 的框架校验结构。

## 4. 六个接口（前端视角）

### 4.1 `GET /health`

- 用在哪：顶部状态灯 / 部署自检。
- 判读：算子探活返回 `status === 1` 且 `operators === 11`。

### 4.2 `GET /operators`

- 用在哪：**算子选择器 + 参数表单**。
- 返回 `data.operators[]`，每条含：`operatorId`、`name`、`tag`、`stage`、`stageId`、`stagePosition`、`isLastOfStage`、`summary`、`outputs`、`paramsSpec`。
- 表单渲染规则：

| `paramsSpec.type` | 控件 |
|---|---|
| `string` | 文本输入框 |
| `int` / `float` | 数字输入框（范围写在 `desc` 里，如「2–50 字」） |
| `bool` | 开关 |
| `enum` | 下拉（`values`） |
| `string[]` | 多选 / 标签输入 |
| `float[2]` | 双输入（区间），如 `snr_db: [5, 15]` |
| `object[]` | 可增删的「行」编辑器（如 `review_decisions`） |
| `object` | 折叠的分组表单（如 `sample_plan`） |
| `int\|int[]` | 数字或多值切换 |

- `required: true` 的字段标红星；`default` 有值就预填；`desc` 放 tooltip；`example` 可做占位符。
- 规格里**没有** `min` / `max` 字段，数值边界写在 `desc` 文案里，前端如需强校验要自己维护。
- **`isLastOfStage` 决定这次 `/predict` 要不要传 `isLastOperator: true`**，别自己写死。

### 4.3 `POST /uploadFile?uniqueId={id}`

- `multipart/form-data`，字段名固定 `file`；支持 zip（自动安全解压）或单个文件。
- 返回 `data.inputFile`（解压目录或单文件路径），后续作为第一个算子的 `inputFile`。
- `uniqueId`：字母数字 `._-`，建议每个任务一个（如 `task_20261104_001`）。
- 上传大 zip 要显示进度；失败按 `path_escape:` / `zip_*` 前缀提示。

### 4.4 `POST /predict`

请求：

```json
{
  "operator": "avp_mix_noise",
  "uniqueId": "task_20261104_001",
  "isLastOperator": false,
  "inputFile": "/data/task_20261104_001/tmp/002/002_std.jsonl",
  "lineageFile": [{ "...": "后端累计保存的完整血缘记录，此处仅为结构示意" }],
  "params": { "dimension": "noise", "values": ["白噪"], "snr_db": [5, 15] }
}
```

- `operator` 接受目录名 / `operatorId` / `tag` / 编号（大小写不敏感），推荐用 `operatorId`。
- 上传后推荐显式传入返回的 `data.inputFile`。只有所需输入已在当前任务的 `input/` 下时才能省略；阶段起点不会自动获取其他任务或业务库里的文件。
- `params` 也可平铺在请求体顶层，但建议统一放 `params` 里。

响应关键字段：

| 字段 | 说明 |
|---|---|
| `data.status` | `success` / `partial` / `failed` |
| `data.statistics` | 各算子的统计（条数、指标、耗时等），用于结果卡片 |
| `data.outputs` | `{名字: "/data/..."}`，前端只展示或交给后端 |
| `data.result` | 业务结果对象（各算子不同，见 §10 与各算子 `DATA_SCHEMA.md`） |
| `data.lineageFile` | **中间算子**是当前记录对象；**阶段末**是列表。由后端累计历史后传给下一步 |
| `data.outputFile` | 仅阶段末：`{main, files:{name:{path,bytes,sha256}}, content:{name:"文本"}}` |

中间算子只返回当前一条血缘。业务后端需累积保存记录，把累计列表作为下一步的 `lineageFile`；仅原样转发最后一条记录会丢失更早的链路历史。阶段末返回列表时，下游输入取最后一条记录的 `outputFile`，或按该算子的业务输入契约选择 `data.outputs` 中对应文件。

`content` 的规则（前端可直接渲染）：

- 只内联 **≤512 KB 的文本类**产物：`.json` `.jsonl` `.md` `.html` `.txt` `.csv` `.tsv`；
- 音频、PDF、zip **永远不内联**，只有 `files[name].path`；
- `main` 是主产物名，11 的 `main` 固定 `report_md`。

### 4.5 `GET /downloadFile?path=完整路径`

工程侧使用完整 path 查询参数，不必传 uniqueId/operatorId。成功返回文件流；参数非法为 400，越界为 403，文件不存在为 404。业务后端保存下载内容并提供页面访问 URL；下一步 predict 仍使用服务端返回路径，不改为下载后的本地路径。下载目录时应改传具体产物文件。

### 4.6 `POST /removeFile?uniqueId={id}`

- 删除该任务整个工作目录（上传、中间产物、输出），**不可恢复**。
- 前端务必二次确认；删除后清空本地任务状态。

## 6. 报告中心（11）怎么渲染

### 6.1 界面卡片 ↔ 报告内容

报告固定八段：结论摘要 / 整体指标 / 分场景表现 / 噪声场景下钻 / 错误形态 / 原因分析 / 优化建议 / 风险与限制。
两种渲染方式任选：**iframe 内联 HTML**（`outputFile.content.report_html`）或前端自己按字段拼（`report_meta.json`）。

| 原型卡片 | 报告里在哪 | 数据来源 |
|---|---|---|
| 头部：报告编号 / 生成时间 / 样本量 / 异常样本 / 对比口径 | 报告头 meta | `report_no`、`generated_at`、`key_numbers`（含 samples / abnormal / cer / wer / ser）、`caliber`（对比口径文案） |
| 结论摘要（整体结论/主要差距/相对优势/原因判断/优化建议） | 第 1 段 5 行 | 007 指标 + 008 主因 + 009 首条建议 |
| 整体指标（3 张 KPI 卡 + 目标线） | 第 2 段 | `metrics` / `baseline_metrics` |
| 分场景表现（场景/样本数/本模型/对比/差距/多错少错） | 第 3 段表 | 007 `dimensions[]` + 008 `factors[].baseline_metric/affected` |
| 噪声场景下钻（取值/样本/本模型/对比/差距/判断） | 第 4 段表 | 同上 + 阈值配置 |
| 错误形态（chips + 模式/典型错误/集中在/对比占比） | 第 5 段 | 007 `error_mix` + `sample_results[].ref_text/hyp_text/perturb` |
| 原因分析（因素/影响/依据 + 原因链条） | 第 6 段 | 008 `factors`、`total_net_error`、`main_cause_detail` |
| 优化建议（判断 / 执行单） | 第 7 段每条建议 | 009 `explanation`、`verification`、`sample_plan` |
| 风险与限制 | 第 8 段 | 输入接入、样本规模、异常率、对比口径、导出边界 |

字段级细节见 `AVP_REPORT_DATA_011/dataset/DATA_SCHEMA.md`，以及报告自身 `011_report_meta.json`。

### 6.2 「下载 PDF」三种做法

报告 HTML 的页脚已经带按钮：

```html
<a class="btn-dl" href="011_report.pdf" download
   data-report-pdf="011_report.pdf" data-report-no="RPT-BENCH-20261104-001">下载 PDF</a>
```

| 方案 | 做法 | 适用 |
|---|---|---|
| **A. 后端下载接口**（推荐） | 前端拿 `outputs.report_pdf`（或 `data-report-pdf`）调你们后端的文件下载接口 | 平台已有文件服务 |
| **B. 同源静态目录** | 后端把 `/data` 挂成 `/files/`，`href` 改成 `/files/<uniqueId>/tmp/011/011_report.pdf` | 最快落地 |
| **C. 直接打开 HTML 目录** | 预览地址用 `/files/<uniqueId>/tmp/011/011_report.html`，相对链接自然可用 | 预览和下载同一目录 |

> **坑**：如果用 `iframe srcdoc` 内联 HTML，相对路径 `011_report.pdf` 会以当前页面为基准 → 404。
> 这时候必须走方案 A/B，把 `href` 替换掉。

`format` 不含 `pdf` 时按钮不渲染，页面只显示「打印另存为 PDF」的说明——不会出现死链。

| 标签 | 渲染 |

## 10. 平台必须补的 4 件事

1. **文件下载 / 试听代理**——算子只回路径（§6.2、§7）。
2. **任务表与进度**——算子无状态、同步、无回调。
3. **跨域或同源反代**——`/uploadFile` 是 multipart，直连易踩 CORS。
4. **超时与异步**——真数据上 02/05/07 几十秒到几分钟，前端别直连长任务。

已联调业务后端支持 07 文件导入 `/evaluations/ingest` 和直接推送 `/evaluations/push`（均加 `/hs-api/speech-adversarial` 前缀），并维护 09 建议状态机。上述都是平台能力，算子服务器仍提供 6 个接口。外部评测任务执行地址需单独配置。

## 11. 联调验收清单（12 条，照着点）

| # | 点这个 | 期望 |
|---|---|---|
| 1 | `/health` | `operators=11`，状态灯绿 |

| 7 | 05 `mode=finalize` 少判一条 | `code=1` + `human_review_incomplete` |
| 8 | 05 全部判完 | `status=success`，结论「通过」，可发布 |
| 9 | 06 `action=publish` 后查版本 | 版本状态由草稿变已发布 |
| 10 | 11 `format=all` | 出 md/html/pdf 三件，`main=report_md`，HTML 有「下载 PDF」 |
| 11 | 点「下载 PDF」 | 真的下到 PDF（方案 A/B 替换过 href），不是 404 |
| 12 | 处理过程面板 | 每次调用都有日志行，失败时也有 |

---

## 12. 常见坑

1. **别用 HTTP 状态码判成败**：业务失败也是 200，看 `code`。
2. **别把 `partial` 画成失败**：黄色「部分完成」，05 start 和 03/04 跳过样本都会出现。
3. **别自己拼 `inputFile`**：依赖上一步产物时使用其返回的 `outputFile`；若血缘是列表，取最后一条记录。各阶段独立输入按算子契约上传或整理。
4. **别把 `/data/...` 当 URL**：那是容器内路径，浏览器打不开。
5. **阶段末才调 `isLastOperator=true`**：按 `/operators` 的 `isLastOfStage` 来，别按页面写死。
6. **`iframe srcdoc` 里的相对下载链接会 404**：见 §6.2 的坑。
7. **11 的报告别自己重算指标**：数字都来自 007/008/009，前端只渲染。
